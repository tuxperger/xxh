# Git в xxh

Общие правила — в скилле `git` (красные линии, разбор состояния, правка истории).
Здесь только то, что специфично для этого репозитория. Разрушающие команды
дополнительно перехватывает хук `git-guard` и требует согласия пользователя.

## Коммиты — автоматически, пуш — по просьбе

Владелец репозитория просил коммитить без вопросов. Закончена фаза `tasks.md` или
фича, гейты зелёные — коммит делается сразу, план коммитов на утверждение не
выносится. Это перекрывает правило общего скилла `git` для этого репозитория.

Не покрыто разрешением и делается только по явной просьбе: `git push`, слияние в
`main`, переписывание уже сделанных коммитов.

Не коммитится то, что не прошло гейты своего уровня (скилл `xxh-quality-gates`):
красный коммит хуже незакоммиченной работы.

## Ветка на фичу

Имя ветки совпадает с каталогом спеки: `003-flake-plugin-source`. Оно же записано
в шапке `spec.md` (`**Feature Branch**`).

```bash
git status --short                       # что уже лежит в дереве
git switch -c 003-flake-plugin-source    # от main, перед /speckit-implement
```

- Ветку создают перед первым коммитом фичи. Пока предыдущая фича не слита в `main`,
  следующая ветка отходит от ветки предыдущей (стопкой) — сливать в `main` самому
  нельзя.
- В дереве могут лежать правки пользователя, не относящиеся к фиче. Их не
  откатывают, не стэшат без спроса и не включают в свои коммиты — стейджить
  только свои пути, поимённо.

## Нарезка коммитов

Один коммит — одна фаза `tasks.md` или одна user story, а не «всё разом»:

1. артефакты spec kit (`specs/NNN-…/`) — отдельным коммитом до кода;
2. Setup + Foundational;
3. по коммиту на user story (код + её тесты вместе);
4. Polish: README, CI, роадмап.

`specs/ROADMAP.md` и отметки `[X]` в `tasks.md` едут в том же коммите, что и
работа, которую они отражают.

## Сообщение

```
<тип>(<область>): <что изменилось, повелительно, до 72 символов>

<зачем — одно-два предложения; что было не так или что стало возможным>

Refs: specs/003-flake-plugin-source (T012–T017, US2)
```

- `тип`: `feat`, `fix`, `test`, `docs`, `refactor`, `build`, `ci`, `spec`
  (`spec` — только артефакты spec kit).
- `область` — крейт без префикса `xxh-` (`plugins`, `transport`, `core`, `cli`,
  `config`) либо `nix`, `bootstrap`, `ci`, `infra`.
- Заголовок на английском (как идентификаторы и комментарии в коде), тело можно
  по-русски.
- `Refs:` обязателен для всего, что сделано под задачи фичи.

Сообщения «Update» в истории — наследие, не образец.

## Что не коммитить

- `target/`, `result`, `result-*`, `.direnv/` — уже в `.gitignore`.
- `tests/images/testkey*/` — эфемерные ключи тестовых хостов. Если такой каталог
  остался после упавшего теста — удалить, а не добавлять.
- `.claude/settings.local.json` с личными разрешениями — не трогать в своих
  коммитах; общие настройки живут в `.claude/settings.json`.
- Любые ключи, токены, `.env*`. Перед `git add` читать diff, а не список файлов.

## Перед PR

1. `.specify/scripts/xxh/gates.sh all` зелёный (скилл `xxh-quality-gates`).
2. В описании PR — ссылка на спеку и явное подтверждение принципов конституции,
   которых фича касается (раздел «Процесс разработки и quality gates»).
3. Поправки в конституцию — отдельным PR.
