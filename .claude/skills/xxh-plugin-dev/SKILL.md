# Плагины xxh

Контракты: `specs/001-portable-shell-over-ssh/contracts/plugin-manifest.md` (C-M*),
`plugin-source-trait.md` (C-S*), `nix-provider.md` (C-N*). Перед изменением
поведения — прочитать соответствующий контракт; изменение контракта оформляется в
`contracts/` текущей фичи.

## Что такое плагин

Каталог с `plugin.toml` в корне и полезной нагрузкой. `env.sh` (если есть)
подключается в init удалённого шелла; `$XXH_COMPONENT_DIR` указывает на каталог
плагина на цели. Шеллы — такие же пакеты с `provides.shell = "<имя>"` и деревом
`dist/<os>-<arch>/bin/<имя>`.

```toml
name = "syntax-highlight"
version = "1.4.0"
api_version = "1.0.0"          # major совпадает с клиентом, не новее клиента
targets = ["linux", "darwin"]  # os[/arch[/libc]], * — любой; пусто = везде
priority = 5                   # больше — раньше; при равенстве — по имени

[dependencies]
base-theme = "^2.0"

[hooks.post_deploy]            # pre_connect | post_deploy | pre_exit
run = "hooks/install.sh"
timeout_s = 20
```

## Путь плагина

```
xxh plugin add <источник>
  └─ SourceSpec::parse ─► provider_for(spec) ─► PackageSource::fetch ─► FetchedPackage
       └─ Registry::store: blake3 дерева ─► packages/<hash>/ + index.toml {source, hash, version}
xxh plugin enable <имя>  ─► enabled_plugins в config.toml (Принцип XI)
xxh <цель>
  └─ session_plugins: манифесты ─► resolver::resolve (зависимости, конфликты, циклы — до доставки)
       └─ Session::establish: компонент на плагин, доставка по хешу, env.sh в init шелла
```

Установленность живёт в реестре (`~/.local/share/xxh/plugins`), включённость — в
конфиге. Хеш содержимого адресует пакет и на клиенте, и на цели: неизменившийся
плагин повторно не передаётся (Принцип VI).

## Новый источник

Источник — деталь за `trait PackageSource`; код, работающий с плагинами, о нём не
узнаёт (Принцип IX). Шаги:

1. **Данные.** Вариант в `SourceSpec` (`source.rs`): только то, что нужно для
   повторного `fetch` при `plugin update`. Он сериализуется в `index.toml` — имена
   полей становятся форматом на диске; старые индексы должны читаться.
2. **Разбор.** Ветка в `SourceSpec::parse` с явным префиксом-схемой. Порядок
   веток важен: новая схема не должна перехватывать существующие формы (git-URL,
   `nixpkgs:`, локальный путь) — на каждую неоднозначность нужен unit-тест.
   `describe()` возвращает форму, которую можно подать обратно в `plugin add`.
3. **Провайдер.** Модуль в `sources/`, реализующий:
   - `id()` — стабильный идентификатор;
   - `availability()` — может ли работать на этом клиенте, с причиной;
   - `supports_target()` — может ли дать артефакт под платформу цели;
   - `fetch()` — каталог с валидным `plugin.toml`, прошедшим `read_manifest`.
4. **Фабрика.** Ветка в `provider_for`. Если провайдер за feature-флагом — вторая
   ветка под `#[cfg(not(feature = …))]` с `PluginError::SourceUnavailable` и
   текстом, что делать.
5. **CLI/доки.** Справка `PluginAction::Add`, README (раздел Plugins).
6. **Тесты.** Unit: разбор, round-trip `SourceSpec` через TOML, недоступность.
   Интеграция: установка → сессия на Alpine → плагин работает → цель чиста
   (скилл `xxh-integration-tests`).

Все ошибки источника — `PluginError` (код возврата 30). Недоступность внешней
программы — `SourceUnavailable`, а не паника и не ошибка транспорта.

## Требования к `fetch`

- Возвращает самодостаточный каталог. Если это временный клон — путь в
  `cleanup`, реестр удалит его после копирования.
- Детерминизм: одинаковый вход → одинаковое содержимое → одинаковый хеш. Не
  клади в пакет метки времени, абсолютные пути клиента, `.git`.
- Сгенерированный манифест (как у Nix-провайдера) получает стабильное имя,
  выводимое из спецификации источника; два разных источника не должны давать
  одно имя молча.
- Бинарь, собранный на клиенте, обязан запускаться на цели без зависимостей:
  статическая линковка, проверка `audit_static` (скилл `xxh-nix`).
- `fetch` не трогает цель и не требует соединения с ней.

## Изменение контракта

- Новое **необязательное** поле манифеста с умолчанием — minor `API_VERSION`.
  Удаление/переосмысление поля, новая обязательность — major (Принцип IV).
- Неизвестные поля манифеста игнорируются (forward-compat) — не включай
  `deny_unknown_fields`.
- Хук плагина исполняется отдельным процессом с ограниченным окружением и
  таймаутом (`isolation.rs`); его сбой — предупреждение класса plugin, сессия
  продолжается.
