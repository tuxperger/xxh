# Rust-код в xxh

## Крейты и направление зависимостей

```
xxh-cli ──► xxh-core ──► xxh-transport
   │           ├───────► xxh-plugins ──► xxh-plugin-api
   └───────────┴───────► xxh-config
```

| Крейт | Отвечает за | Не знает о |
| --- | --- | --- |
| `xxh-plugin-api` | манифест `plugin.toml`, `PluginError`, `API_VERSION` | всём остальном |
| `xxh-plugins` | `PackageSource`, реестр, резолвер, изоляция хуков | транспорте, сессии |
| `xxh-transport` | `trait Transport` и бэкенды (russh, ssh, container) | плагинах, конфиге |
| `xxh-config` | канонический `config.toml`, precedence, JSON-схема | транспорте, плагинах |
| `xxh-core` | сессия: connect → detect → deploy → PTY → cleanup | конкретном бэкенде и источнике |
| `xxh-cli` | clap, сборка `Effective`, коды возврата | — |

Конституция запрещает ветвления по способу доступа и способу поставки в
вызывающем коде: `xxh-core` работает только через `trait Transport` (Принцип III),
реестр — только через `trait PackageSource` (Принцип IX). Новая реализация
добавляется новым модулем и одной веткой в фабрике (`provider_for`,
выбор бэкенда в `xxh-cli`), а не `if` в бизнес-логике.

## Ошибки — по классам

Пользователь различает класс ошибки по сообщению и коду возврата (Принцип VII):

| Класс | Тип | Код |
| --- | --- | --- |
| transport | `xxh_transport::TransportError` | 10 |
| shell | `xxh_core::ShellError` | 20 |
| plugin | `xxh_plugin_api::PluginError` | 30 |
| config | `xxh_config::ConfigError` | 40 |

- Новая ошибка — вариант существующего класса, а не новый класс и не `anyhow` в
  библиотечном крейте. `anyhow` допустим только в `xxh-cli`.
- Текст ошибки отвечает на два вопроса: что случилось и что сделать. Пример —
  `ShellError::NotAvailable`.
- Сбой источника плагина — всегда `PluginError`, даже если причиной был сетевой
  отказ `git` или `nix` (Принцип IX).
- В сообщения и логи не попадают секреты: пути к ключам можно, содержимое, пароли
  и токены в URL — нет. Для сомнительного значения есть `xxh_core::redact`.

## feature `nix-source`

Всё, что требует Nix на клиенте, компилируется за
`#[cfg(feature = "nix-source")]` в `xxh-plugins` и пробрасывается через
`xxh-core` → `xxh-cli`. Без фичи инструмент обязан собираться и на обращение к
Nix-источнику отвечать `PluginError::SourceUnavailable` с понятным текстом.
Данные (`SourceSpec`) существуют в обоих вариантах сборки — за `cfg` прячется
только провайдер.

## Жёсткие правила

- `unsafe_code = "deny"` на весь workspace. Единственное допустимое исключение —
  `std::env::set_var` в тестах, с `// SAFETY:` и локальным `#[allow(unsafe_code)]`.
- Версии зависимостей — только в `[workspace.dependencies]` корневого
  `Cargo.toml`; в крейтах `foo.workspace = true`. Новая зависимость должна
  собираться под `*-unknown-linux-musl` статически (Принцип II) — никаких
  `openssl-sys` и подобного, что тянет системные библиотеки.
- MSRV 1.85, edition 2024. Тулчейн один — `rust-toolchain.toml`.
- Внешние программы (`git`, `nix`, `docker`, `ssh`) вызываются массивом
  аргументов, без `sh -c` со склейкой строк. Пользовательский ввод не
  интерполируется в командную строку.
- То, что исполняется на цели, — POSIX `sh` в рамках BusyBox: без bash-измов,
  без `local`, без GNU-флагов.

## Комментарии

Модуль открывается `//!`-шапкой: что это, какой задаче и какому требованию
соответствует — `(T032, Принцип IX)`, `(§FR-026)`, `(C-S2)`. Для новых фич ссылка
включает номер фичи: `(003 T014, §FR-007)`. Комментарий в теле объясняет
«почему», а не пересказывает код. Язык комментариев и идентификаторов — английский.

## Unit-тесты

- В том же файле, `#[cfg(test)] mod tests`.
- Тест, меняющий переменные окружения процесса, держит общий замок (образец —
  `shellpkg::testenv::shells_dir`), иначе тесты гонятся между собой.
- Временные каталоги — под `std::env::temp_dir()` с pid/наносекундами в имени и
  явным удалением в конце.
- Каталоги клиента переопределяются переменными: `XXH_PLUGINS_DIR`,
  `XXH_SHELLS_DIR`, `XXH_NIX_CACHE_DIR`. Тест не пишет в настоящий `~/.local/share`.

## Конфиг

Новое поле `Config`/`HostOverride` тянет за собой четыре места (Принцип XI):
типы в `xxh-config`, `nix/config-schema.json`
(`XXH_REGEN_SCHEMA=1 cargo test -p xxh-config schema`), опции в
`nix/modules/common.nix`, значение в `tests/nix-modules/roundtrip.nix`.
Подробности — скилл `xxh-nix`.
