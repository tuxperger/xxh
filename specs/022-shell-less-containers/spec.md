# Feature Specification: Контейнеры без шелла (distroless, scratch)

**Feature Branch**: `022-shell-less-containers`

**Created**: 2026-10-01

**Status**: Draft

**Priority**: P3

**Summary**: Войти со своим окружением в контейнер, где нет даже `sh`, — для отладки distroless-образов

**Input**: User description: "Distroless/scratch-контейнеры: в спеке 002 это вне MVP (явная ошибка); решается доставкой статического набора базовых утилит как первого шага развёртывания."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Отладка контейнера без шелла (Priority: P1)

Сервис работает в минимальном образе без шелла и утилит. Пользователь входит в
запущенный контейнер и получает свой шелл с инструментами, чтобы посмотреть файлы,
процессы и сеть изнутри; образ не изменён, после выхода контейнер чист.

**Why this priority**: именно в таких контейнерах отладочных средств нет вовсе, и своё
окружение там ценнее всего; сегодня xxh отказывает с ошибкой доставки.

**Independent Test**: запустить контейнер из образа без шелла, войти, выполнить команду
в своём окружении, выйти; убедиться, что образ не изменён и в контейнере чисто.

**Acceptance Scenarios**:

1. **Given** запущенный контейнер без `sh`, **When** пользователь входит в него,
   **Then** он получает сессию своего шелла.
2. **Given** сессия завершена, **When** проверяется контейнер, **Then** всё доставленное
   удалено, включая вспомогательные средства развёртывания.
3. **Given** любой исход, **When** проверяется образ, **Then** он не изменён.
4. **Given** контейнер с обычным `sh`, **When** пользователь входит, **Then** поведение
   и время входа не отличаются от прежних.

---

### User Story 2 - Понятный отказ, когда доставка невозможна (Priority: P2)

Если рантайм или контейнер не позволяют положить внутрь ни одного файла (нет доступной
для записи области, запрещено копирование), пользователь получает объяснение и варианты.

**Why this priority**: часть distroless-контейнеров запущена с файловой системой только
для чтения; молчаливый или невнятный отказ недопустим.

**Independent Test**: контейнер только для чтения без временной области — ошибка
называет причину и предлагаемые действия; контейнер не изменён.

**Acceptance Scenarios**:

1. **Given** в контейнере нет области, доступной для записи, **When** пользователь
   входит, **Then** выдаётся ошибка с причиной, ничего не записано.
2. **Given** платформа контейнера не поддерживается, **When** пользователь входит,
   **Then** ошибка выдаётся до доставки.

---

### Edge Cases

- В контейнере нет ни одной утилиты для определения платформы — платформа определяется
  средствами рантайма снаружи.
- Нет домашнего каталога или пользователь не имеет его — используется доступная
  временная область.
- Процесс в контейнере работает от непривилегированного пользователя без прав записи
  куда-либо.
- Аварийное завершение сессии — вспомогательные средства тоже должны быть удалены;
  обычный механизм очистки опирается на шелл, которого в контейнере нет.
- Контейнер завершился во время сессии.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST обнаруживать отсутствие шелла в контейнере и переходить к
  доставке без опоры на утилиты контейнера.
- **FR-002**: Система MUST доставлять в контейнер минимальный самодостаточный набор
  средств, необходимый для развёртывания окружения, под платформу контейнера.
- **FR-003**: Платформа контейнера MUST определяться без исполнения утилит контейнера,
  если их нет.
- **FR-004**: Образ и его слои MUST NOT модифицироваться.
- **FR-005**: Всё доставленное, включая вспомогательные средства, MUST удаляться при
  выходе, в том числе при аварийном завершении.
- **FR-006**: Если доставка в контейнер невозможна, система MUST выдать ошибку с
  причиной до каких-либо изменений в контейнере.
- **FR-007**: Для контейнеров с шеллом поведение MUST остаться прежним.
- **FR-008**: Возможность MUST быть покрыта интеграционным сценарием против реального
  рантайма с образом без шелла, с проверкой чистоты и неизменности образа.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Пользователь получает свой шелл в контейнере из образа без шелла той же
  командой, что и для обычного контейнера.
- **SC-002**: После выхода в контейнере нет ни одного доставленного файла, образ не
  изменён — в 100% сценариев.
- **SC-003**: Время входа в контейнер с шеллом не увеличивается.
- **SC-004**: В случаях, когда доставка невозможна, пользователь узнаёт причину из
  одного сообщения.

## Assumptions

- Продолжение фичи 002, где этот случай зафиксирован как расширение на будущее.
- Относится к контейнерным целям; SSH-хост без `sh` не рассматривается (без шелла
  невозможен сам вход по SSH).
- Те же приёмы применимы к подам Kubernetes (фича 016); запуск отдельного отладочного
  контейнера рядом с целевым — иной подход и вне рамок.
