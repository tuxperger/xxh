# Contract: `xxh shell` (C-SH*)

```
xxh shell add <источник> [--platform <os-arch>]... [--no-builds]
xxh shell fetch <шелл> [--platform <os-arch>]... [--all]
xxh shell list
xxh shell update [<шелл>]
xxh shell remove <шелл>
```

`<источник>` — как у `xxh plugin add` (git-URL, путь, …).

- **C-SH1** `add`: устанавливает пакет в `<shells>/<шелл>`; по умолчанию — все
  объявленные сборки Linux; `--platform` — явный набор; `--no-builds` — без сборок.
  Не пакет шелла (нет `provides.shell`) — ошибка. Шелл уже установлен из другого
  источника или подключён вручную — ошибка конфликта с подсказкой
  `xxh shell remove <шелл>` (FR-009); тот же источник — обновление.
- **C-SH2** `fetch`: загружает указанные (или все, `--all`) сборки; без флагов — все
  Linux-сборки. Уже загруженная с той же суммой — пропускается без сети. Платформа,
  которой нет в манифесте, — ошибка с перечнем объявленных платформ.
- **C-SH3** `list`: по строке на шелл — имя, версия, источник (или `linked`), затем
  платформы: загруженные и объявленные-но-незагруженные. Пусто —
  `no shell packages installed`.
- **C-SH4** `update`: для установленных командой пакетов — повторная загрузка
  пакета и изменившихся сборок; подключённые вручную — пропускаются с сообщением.
- **C-SH5** `remove`: удаляет каталог пакета; для ручного подключения-ссылки —
  только ссылку. Шелл по умолчанию в конфиге — предупреждение в stderr.
- **C-SH6**: все ошибки — класс shell, код 20 (FR-010); вывод прогресса загрузки — в
  stderr.

## Вход (FR-007)

- **C-SH7**: нет сборки под платформу цели — заметка/ошибка/действие doctor
  содержат `xxh shell fetch <шелл> --platform <os-arch>`.
