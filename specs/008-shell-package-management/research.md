# Research: Управление пакетами шеллов из CLI

## R1. Как добываются сборки

- **Decision**: декларация в манифесте (решение пользователя 2026-10-01):

  ```toml
  [builds.linux-x86_64]
  url = "https://…/zsh-5.8-linux-x86_64.tar.gz"
  sha256 = "6df668fb…"
  strip = 0            # ведущих компонентов пути отбросить (умолчание 0)
  ```

  Ключ — `os-arch` в именах xxh (`Platform::target_key`). Сумма сверяется с
  архивом **до** распаковки (FR-005).
- **Alternatives**: запуск `fetch.sh` пакета — xxh не видел бы скачанный архив и
  проверял бы только итог; отвергнуто пользователем.

## R2. Скачивание

- **Decision**: `curl -fsSL --proto =https,file -o <tmp> <url>` массивом аргументов;
  нет `curl` — `ShellError::Package` с действием.
- **Rationale**: как `git` для git-источника; не тянет HTTP/TLS-стек в статический
  бинарь. `--proto` запрещает прочие схемы (V). `file://` — для тестов и зеркал.

## R3. Распаковка

- **Decision**: формат по сигнатуре (gzip `1f 8b`, zstd `28 b5 2f fd`, иначе tar);
  `tar`-крейт, каждая запись: отбросить `strip` компонентов, отвергнуть абсолютные
  пути, `..`, и запись через симлинк, ведущий из каталога; жёсткие ссылки наружу
  тоже отвергаются. Распаковка — в `dist/.tmp-<платформа>-<pid>`.
- **Rationale**: архив чужой; выход за каталог — классическая уязвимость.

## R4. Доводка сборки

- **Decision**: после распаковки — копия `overlay/` пакета поверх дерева (общие
  файлы, напр. `env.sh`), затем хук `[hooks.post_fetch]` (если есть) через
  `isolation::run_hook` с `XXH_BUILD_DIR`, `XXH_BUILD_PLATFORM`; его сбой отклоняет
  сборку (в отличие от хуков сессии). Затем проверка `bin/<шелл>` и `rename` в
  `dist/<платформа>`.
- **Rationale**: zsh-bin требует переименовать каталоги terminfo — логика пакета,
  а не ядра (FR-008). Временный каталог начинается с `.` — поиск шеллов и `list` его
  не видят (FR-006); остатки прерванных загрузок удаляются следующим `fetch`.

## R5. Где живут пакеты

- **Decision**: `<shells>/<шелл>/` (первый каталог пути поиска): копия дерева
  пакета без `dist/` и `.git`, `dist/`, `.xxh-shell.toml` (`source`, `builds =
  {платформа = sha256}`). Пакет без этого файла — «подключён вручную».
- **Rationale**: вход уже ищет именно там (`shellpkg`); реестр плагинов
  неизменяем по содержимому, а сборки добавляются позже.

## R6. Источник, обновление, конфликт

- **Decision**: `add` — `provider_for(spec).fetch()` (те же источники, FR-002); шелл —
  `provides.shell` манифеста (нет — ошибка «это не пакет шелла»). Если
  `<shells>/<шелл>` уже есть: тот же источник — обновление; другой источник или
  ручное подключение — конфликт с подсказкой `xxh shell remove` (FR-009).
  `update` — повторный `fetch` по записанному источнику, замена дерева пакета с
  сохранением `dist/`, перезагрузка сборок, чья сумма в манифесте изменилась,
  удаление сборок, которых больше нет в манифесте.

## R7. Версия контракта манифеста

- **Decision**: `API_VERSION` 1.0.0 → 1.1.0: необязательные `builds` и стадия хука
  `post_fetch`. Пакет zsh объявляет `api_version = "1.1.0"`.
- **Rationale**: новое необязательное поле — minor (Принцип IV, скилл
  xxh-plugin-dev).

## R8. Сообщения о недостающей сборке (FR-007)

- **Decision**: `ShellError::NoBuild`, заметка входа и действие `doctor` называют
  `xxh shell fetch <шелл> --platform <ос-арх>`.
