# Research: передача переменных окружения в сессию

## R1. Как значения попадают на цель

- **Decision**: клиент собирает из действующего набора переменных текст
  `NAME='значение'; export NAME` (одинарные кавычки, `'` → `'\''`) и передаёт его
  **через stdin** команды bootstrap `env <sid>`, которая пишет файл
  `<root>/run/<sid>/env` (каталог 0700, файл 0600, `umask 077`). Прелюдия сессии
  после `env.sh` всех компонентов делает `. <файл>; rm -f <файл>` и только затем
  `exec` шелла или команды.
- **Rationale**:
  - FR-008 «не видны другим пользователям цели»: значения не попадают ни в argv
    (`ps` показывает командную строку `sh -c '<прелюдия>'` всем), ни в файлы,
    доступные другим (корень 0700, файл 0600). В окружении процесса их видит
    только владелец и root — как у любой переменной, выставленной в шелле.
  - FR-004: одинарные кавычки POSIX `sh` передают любые байты, кроме NUL, без
    интерпретации — включая переводы строк, `$`, `` ` ``, `\` и кавычки.
  - Принцип I: файл живёт до первой строки прелюдии; его удаляет сама прелюдия,
    а при сбое — очистка сессии (R3).
  - FR-009: прелюдия общая у интерактивной сессии и режима одной команды.
- **Alternatives**:
  - Переменные в командной строке (`env K=V sh …`) — видны в `ps` на цели;
    отклонено (FR-008).
  - Запрос `env` канала SSH / `docker exec -e` — sshd по умолчанию отвергает
    (`AcceptEnv`), у контейнера значение попадает в аргументы клиента рантайма и
    в `docker inspect` exec-сессии; поведение разное у транспортов (Принцип III);
    отклонено.
  - Компонент в `cache/` — адрес по содержимому сохранил бы значения на цели при
    `--keep` и показал бы их в `xxh status`; отклонено (FR-008, Принцип I).

## R2. Порядок и приоритет

- **Decision**: действующий набор = `[env]` → поверх по имени
  `[hosts.<цель>.env]` → поверх по имени флаги `--env` (FR-003). В прелюдии файл
  переменных подключается **последним**, после `env.sh` плагинов, шелла и файлов
  (010): пользователь может переопределить переменную плагина (допущение спеки).
- **Служебные переменные**: имена с префиксом `XXH_` отклоняются как ошибка
  конфигурации (FR-007): ими bootstrap и компоненты находят свои пути
  (`XXH_ROOT`, `XXH_COMPONENT_DIR`, `XXH_SESSION`). Прочие имена, включая `PATH`,
  разрешены: переопределение — осознанный выбор пользователя; шелл запускается
  по абсолютному пути и от `PATH` не зависит.

## R3. Очистка файла переменных

- **Decision**: `run/<sid>/` — каталог одной сессии. Очистка сессии
  (`xxh_cleanup`) в режиме `--keep` удаляет только свой `run/<sid>`, а не весь
  `run/` (сейчас удаляется весь — это задело бы файл параллельной сессии, ещё не
  подключённый). Reconcile, снимая метку мёртвой сессии, удаляет и её
  `run/<sid>`. Эфемерная очистка по-прежнему удаляет корень целиком.
- **Rationale**: FR-008 и Принцип I при параллельных сессиях с `--keep`.
- **Остаточный риск**: обрыв между загрузкой файла и запуском `run` (метки ещё
  нет) с `--keep` оставит `run/<sid>/env` до `xxh clean`. Окно — один обмен
  командами; `xxh clean` и эфемерный вход удаляют его. Задокументировано.

## R4. Флаг

- **Decision**: `-e, --env NAME=VALUE` и `-e, --env NAME`, повторяемый, глобальный
  для входа и режима одной команды. Без `=` берётся значение с клиента; если
  переменной на клиенте нет — предупреждение `xxh: warning: env: NAME is not set
  here — skipped` (имя, без значений), вход продолжается.
- **Rationale**: SC-003, US1/AC3; `-e` свободен и привычен по `docker run -e`.
- Флаг после `--` принадлежит команде, как и прочие флаги (004).

## R5. Проверка имён и значений

- **Decision**: имя — `[A-Za-z_][A-Za-z0-9_]*`, не начинается с `XXH_`;
  значение — без байта NUL (его не может нести ни переменная окружения, ни строка
  `sh`). Нарушение — ошибка класса config (40) до подключения, в том числе для
  `xxh config validate`. Сообщение называет имя, но не значение.

## R6. Где значения не показываются

- **Decision**: значения не печатаются нигде в выводе xxh: ни в стадиях `-v`/`-vv`
  и `--debug`, ни в предупреждениях и ошибках, ни в `xxh config show` (показывает
  `env.NAME = <set>`), ни в `doctor`/`status`. Исключение — `xxh config get
  env.NAME`: явный запрос значения из своего файла, не журнал.
- **Rationale**: FR-008, SC-002. Интеграционный тест ищет значение в stderr при
  `-vv`.

## R7. Декларативные модули

- **Decision**: опция `env` (`attrsOf str`, имя проверяется `strMatching`) и
  `hosts.<имя>.env` (`nullOr (attrsOf str)`); рендер в `[env]` и
  `[hosts.<имя>.env]`. Round-trip — через `xxh config show`.
- **Rationale**: FR-010, Принцип XI.
