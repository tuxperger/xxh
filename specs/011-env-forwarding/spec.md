# Feature Specification: Передача переменных окружения в сессию

**Feature Branch**: `011-env-forwarding`

**Created**: 2026-10-01

**Status**: Draft

**Priority**: P2

**Summary**: Задать переменные окружения сессии флагом или в конфиге — глобально и по хостам

**Input**: User description: "Проброс переменных окружения: `--env KEY=VAL` и `env = {...}` в конфиге, глобально и по хостам."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Переменная на одну сессию (Priority: P1)

Пользователь задаёт переменную флагом при входе, и она видна в сессии — например,
чтобы включить отладку инструмента или выбрать профиль.

**Why this priority**: самый частый разовый сценарий; не требует правки конфига.

**Independent Test**: `xxh <цель> --env FOO=bar`, в сессии `echo $FOO` даёт `bar`.

**Acceptance Scenarios**:

1. **Given** флаг с парой имя=значение, **When** пользователь входит, **Then**
   переменная установлена в сессии с точным значением, включая пробелы и спецсимволы.
2. **Given** флаг указан несколько раз, **When** пользователь входит, **Then**
   установлены все переменные.
3. **Given** флаг только с именем, **When** пользователь входит, **Then** в сессию
   передаётся текущее значение этой переменной с клиента.

---

### User Story 2 - Постоянные переменные в конфиге (Priority: P2)

Пользователь задаёт в конфиге переменные, которые должны быть в каждой сессии, и
переопределяет их для отдельных хостов.

**Why this priority**: редактор по умолчанию, локаль, настройки инструментов —
постоянная часть личного окружения.

**Independent Test**: глобально `EDITOR=nvim`, для хоста `web` — `EDITOR=vi`; значения
в сессиях соответствуют.

**Acceptance Scenarios**:

1. **Given** переменные в глобальной секции, **When** пользователь входит на любую
   цель, **Then** они установлены.
2. **Given** переопределение для хоста, **When** пользователь входит на этот хост,
   **Then** действует значение хоста.
3. **Given** одна переменная задана в конфиге и флагом, **When** пользователь входит,
   **Then** действует значение флага.

---

### Edge Cases

- Недопустимое имя переменной — ошибка конфигурации/использования до подключения.
- Переменная конфликтует с той, что выставляет плагин или сам xxh, — определён и
  документирован порядок, служебные переменные xxh переопределить нельзя.
- Значение многострочное или содержит кавычки — доходит без искажений.
- Значение является секретом — не появляется в выводе и журналах, не видно в списке
  процессов цели.
- Запрошена передача переменной с клиента, которой там нет, — предупреждение.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Пользователь MUST иметь возможность задать переменные окружения сессии
  флагом командной строки, в том числе несколько раз.
- **FR-002**: Пользователь MUST иметь возможность задать переменные в конфигурации
  глобально и для отдельных хостов.
- **FR-003**: Приоритет MUST быть: флаг > настройка хоста > глобальная настройка.
- **FR-004**: Значения MUST доставляться в сессию без искажений независимо от
  содержимого.
- **FR-005**: Система MUST поддерживать передачу текущего значения переменной с клиента
  по её имени.
- **FR-006**: Недопустимые имена переменных MUST отклоняться до подключения.
- **FR-007**: Служебные переменные xxh MUST NOT переопределяться пользовательскими.
- **FR-008**: Значения переменных MUST NOT появляться в выводе и журналах xxh на любом
  уровне детализации и MUST NOT быть видимы другим пользователям цели.
- **FR-009**: Переменные MUST действовать для интерактивной сессии и для выполнения
  отдельной команды одинаково.
- **FR-010**: Возможность MUST быть доступна через канонический конфиг и декларативные
  генераторы в одинаковом объёме.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Переменная, заданная любым из способов, имеет в сессии побайтно то же
  значение.
- **SC-002**: Ни одно значение переменной не обнаруживается в выводе и журналах xxh.
- **SC-003**: Пользователь задаёт переменную на сессию одним флагом, без правки файлов.

## Assumptions

- Порядок относительно плагинов: пользовательские переменные применяются после
  переменных плагинов, чтобы пользователь мог их переопределить.
- Постоянное хранение секретов и интеграция с менеджерами секретов — вне рамок.
- Перенос файлов — фича 010; режим одной команды — фича 004.
