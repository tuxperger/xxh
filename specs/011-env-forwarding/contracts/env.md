# Contract: переменные окружения сессии (C-E*)

## Объявление

```toml
[env]
EDITOR = "nvim"
LANG = "en_US.UTF-8"

[hosts.web.env]
EDITOR = "vi"                     # заменяет глобальное значение на этом хосте
```

```sh
xxh web -e DEBUG=1 -e 'GREETING=a b "c"' -e AWS_PROFILE   # последнее — значение с клиента
xxh web -e DEBUG=1 -- printenv DEBUG                      # то же в режиме одной команды
```

- **C-E1**: `[env]` и `[hosts.<цель>.env]` — таблицы строк; ключ — имя переменной.
  Флаг `-e, --env` повторяется: `NAME=VALUE` — значение как есть (всё после первого
  `=`, в том числе пустое), `NAME` — текущее значение переменной на клиенте.
- **C-E2**: имя — `[A-Za-z_][A-Za-z0-9_]*` и не начинается с `XXH_`; значение не
  содержит NUL. Нарушение во флаге или в конфиге — ошибка config (40) до
  подключения; `xxh config validate` сообщает о нём так же. Сообщение называет
  имя и правило, но не значение.
- **C-E3**: действующий набор: `[env]`, поверх по имени `[hosts.<цель>.env]`,
  поверх по имени флаги (последний одноимённый флаг побеждает).
- **C-E4**: `NAME` без значения, которого нет на клиенте, — предупреждение
  `xxh: warning: env: NAME is not set here — skipped` (показывается и без `-v`),
  вход продолжается без этой переменной.

## В сессии

- **C-E5**: каждая переменная действующего набора выставлена и экспортирована в
  интерактивной сессии и в режиме одной команды (`--`, `-c`, `-t`) с побайтно тем
  же значением.
- **C-E6**: переменные пользователя применяются после `env.sh` всех компонентов
  (шелл, плагины, файлы 010): одноимённая переменная пользователя побеждает.
  Стартовые файлы самого шелла (rc) выполняются позже и могут её переопределить —
  это конфигурация пользователя, а не xxh.
- **C-E7**: пустой действующий набор не меняет ничего на цели (нет файла, нет
  лишних команд).

## Безопасность (Принцип V)

- **C-E8**: значения передаются на цель только по каналу транспорта, через stdin;
  в командных строках на цели (видимых в `ps`) их нет.
- **C-E9**: на цели значения лежат только в `<root>/run/<sid>/env` (каталог 0700,
  файл 0600) от загрузки до начала прелюдии, которая файл удаляет. Очистка сессии
  удаляет `run/<sid>` в любом режиме; reconcile удаляет `run/<sid>` мёртвых
  сессий. В `cache/` значения не попадают никогда.
- **C-E10**: значения не выводятся xxh ни в stdout, ни в stderr — на любом уровне
  подробности, в предупреждениях и ошибках; `xxh config show` печатает
  `env.NAME = <set>`. Единственное исключение — `xxh config get env.NAME`.

## Генераторы

- **C-E11**: модули Home Manager и NixOS принимают `env` и `hosts.<имя>.env` и
  порождают те же ключи `config.toml`; неверное имя падает на eval.
