# Feature Specification: Вход дальше с цели со своим окружением

**Feature Branch**: `018-nested-sessions`

**Created**: 2026-10-01

**Status**: Draft

**Priority**: P3

**Summary**: Из сессии xxh пойти на следующий хост или в контейнер на этом хосте — и окружение идёт следом

**Input**: User description: "Вложенный вход (xxh изнутри сессии xxh): доставка себя на хост для прыжка дальше через bastion или в контейнер, запущенный на удалённом хосте."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Контейнер на удалённом хосте (Priority: P1)

Пользователь на удалённом сервере в своей сессии хочет зайти в контейнер, запущенный
на этом сервере, с тем же окружением.

**Why this priority**: локальный рантайм контейнеров клиента до удалённых контейнеров
не дотягивается; это самый частый случай, не закрываемый существующими транспортами.

**Independent Test**: в сессии на хосте выполнить `xxh docker:<контейнер>`, получить
своё окружение в контейнере, выйти из обоих уровней, убедиться в чистоте хоста и
контейнера.

**Acceptance Scenarios**:

1. **Given** сессия xxh на хосте, где запущен контейнер, **When** пользователь выполняет
   в ней `xxh <контейнерная цель>`, **Then** он получает своё окружение в контейнере.
2. **Given** вложенная сессия завершена, **When** проверяется контейнер, **Then** он
   чист; **When** завершена внешняя сессия, **Then** чист и хост.

---

### User Story 2 - Следующий хост за bastion (Priority: P2)

Пользователь из сессии на промежуточном хосте идёт на внутренний хост, недоступный с
клиента напрямую, и окружение переносится дальше.

**Why this priority**: полезно там, где прямой проход через промежуточный хост запрещён
политикой; в остальных случаях закрывается фичей 012.

**Independent Test**: клиент → хост A → хост B; на B своё окружение; после выхода чисты
оба.

**Acceptance Scenarios**:

1. **Given** сессия на хосте A, **When** пользователь выполняет `xxh <хост B>`, **Then**
   на B разворачивается то же окружение.
2. **Given** платформа B отличается от платформы A, **When** выполняется вход, **Then**
   окружение для B либо доставлено корректно, либо выдана явная ошибка о том, что для
   этой платформы компонентов на A нет.

---

### Edge Cases

- На промежуточной цели нет сборки клиента под её платформу — команда недоступна, с
  объяснением при попытке включить возможность.
- Ключи для следующего хоста — используются только при явно разрешённом пробросе
  агента; приватные ключи на цель не копируются никогда.
- Глубина вложенности — ограничена, превышение даёт понятную ошибку.
- Обрыв внешней сессии — вложенные сессии завершаются, очистка гарантирована на всех
  уровнях.
- Конфигурация клиента не должна утекать на промежуточную цель сверх необходимого.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Пользователь MUST иметь возможность включить доступность xxh внутри
  сессии; по умолчанию она выключена.
- **FR-002**: Из сессии xxh пользователь MUST иметь возможность войти на следующую цель
  любого поддерживаемого семейства с тем же окружением.
- **FR-003**: Приватные ключи и иные секреты клиента MUST NOT копироваться на
  промежуточную цель.
- **FR-004**: Очистка MUST быть гарантирована на каждом уровне вложенности, включая
  обрыв любого из соединений.
- **FR-005**: Всё, что доставляется на промежуточную цель для вложенного входа, MUST
  подчиняться общим правилам размещения, кеширования и очистки.
- **FR-006**: Если для платформы следующей цели на промежуточной цели нет нужных
  компонентов, система MUST выдать явную ошибку до записи на следующую цель.
- **FR-007**: Глубина вложенности MUST быть ограничена с понятным сообщением при
  превышении.
- **FR-008**: Ошибки вложенного входа MUST сохранять классы (транспорт, шелл, плагин).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Пользователь попадает со своим окружением в контейнер на удалённом хосте
  одной командой из сессии.
- **SC-002**: После выхода из всех уровней все затронутые цели чисты в 100% сценариев,
  включая обрыв внешнего соединения.
- **SC-003**: На промежуточных целях не обнаруживается ни одного приватного ключа или
  иного секрета клиента.

## Assumptions

- Зависит от наличия статических сборок клиента под платформы целей и от фичи 012
  (проброс агента).
- Альтернатива для SSH-цепочек — прямой проход через промежуточные хосты (фича 012);
  эта фича нужна там, где он невозможен, и для контейнеров на удалённых хостах.
