# Feature Specification: Цели на macOS и BSD

**Feature Branch**: `017-macos-bsd-hosts`

**Created**: 2026-10-01

**Status**: Draft

**Priority**: P3

**Summary**: Своё окружение на удалённых macOS- и BSD-хостах с теми же гарантиями, что и на Linux

**Input**: User description: "macOS/BSD-хосты: в README помечено как planned; нужны сборки шеллов под эти платформы и расширение определения платформы. Конституция (Принцип II) включает macOS и BSD в матрицу целевых хостов."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Вход на macOS-хост (Priority: P1)

Пользователь входит на удалённый Mac (сборочная машина, рабочая станция) и получает
свой шелл и плагины так же, как на Linux-хосте; после выхода хост чист.

**Why this priority**: macOS — самая распространённая не-Linux цель; конституция
требует её в матрице.

**Independent Test**: вход на macOS-хост обеих архитектур, команда в окружении, выход,
проверка чистоты.

**Acceptance Scenarios**:

1. **Given** macOS-хост и установленный пакет шелла со сборкой под него, **When**
   пользователь входит, **Then** он получает сессию своего шелла с плагинами.
2. **Given** плагин, ограниченный Linux, **When** пользователь входит на macOS-хост,
   **Then** плагин пропущен с предупреждением, сессия работает.
3. **Given** сессия завершена, **When** проверяется хост, **Then** артефактов нет.

---

### User Story 2 - Вход на BSD-хост (Priority: P2)

То же для FreeBSD и родственных систем.

**Why this priority**: меньшая аудитория, но те же требования конституции.

**Independent Test**: вход на FreeBSD-хост, команда в окружении, выход, чистота.

**Acceptance Scenarios**:

1. **Given** FreeBSD-хост и подходящая сборка шелла, **When** пользователь входит,
   **Then** он получает сессию своего шелла.
2. **Given** для платформы хоста нет сборки шелла, **When** пользователь входит,
   **Then** до записи на хост выдаётся ошибка с указанием, чего не хватает.

---

### Edge Cases

- Системные утилиты отличаются от GNU и BusyBox (другие флаги `tar`, `stat`, `mktemp`) —
  развёртывание и очистка не полагаются на расширения.
- Защитные механизмы платформы блокируют запуск доставленных исполняемых файлов
  (карантин, подпись) — диагностируется явно.
- Домашний каталог на файловой системе без учёта регистра.
- Плагины из Nix-источников, собранные только под Linux, — пропускаются с объяснением.
- Неизвестная версия ОС или архитектура — явная ошибка до записи.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST определять macOS и BSD-системы и их архитектуру до доставки.
- **FR-002**: Развёртывание, запуск сессии и очистка MUST работать на этих платформах
  штатными средствами системы, без установки чего-либо и без root.
- **FR-003**: Система MUST доставлять сборку шелла, соответствующую платформе хоста, и
  MUST выдавать явную ошибку до записи на хост, если такой сборки нет.
- **FR-004**: Плагины, несовместимые с платформой хоста, MUST пропускаться с
  предупреждением.
- **FR-005**: Гарантии zero-footprint, кеширования и очистки при сбое MUST быть теми же,
  что на Linux.
- **FR-006**: Блокировка запуска доставленных файлов защитными механизмами платформы
  MUST диагностироваться с понятным сообщением.
- **FR-007**: Поддержка новых платформ MUST NOT ухудшать поведение на Linux.
- **FR-008**: Каждая добавленная платформа MUST быть покрыта автоматической проверкой
  сценария «вход → свой шелл → выход → чисто».

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Сценарий «вход → свой шелл → выход → чисто» проходит на macOS (обе
  архитектуры) и на FreeBSD.
- **SC-002**: На неподдерживаемой платформе на хост не записывается ни одного байта.
- **SC-003**: Матрица Linux-целей проходит без регрессий.
- **SC-004**: Пользователь не меняет ни команду, ни конфигурацию для входа на хост
  другой ОС.

## Assumptions

- Сборки шеллов под новые платформы поставляются пакетами шеллов (фича 008); эта фича
  обеспечивает их выбор и доставку.
- Статическая линковка в смысле Linux на macOS неприменима; «самодостаточность»
  означает зависимость только от системных библиотек, присутствующих всегда.
- Автоматическая проверка требует соответствующих исполнителей CI; их доступность —
  внешняя зависимость.
- Клиент на macOS уже поддерживается и здесь не рассматривается.
