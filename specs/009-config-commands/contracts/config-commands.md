# Contract: `xxh config …` (C-G*)

Все команды работают без подключения к целям. Любая ошибка — класс `config`, код 40,
сообщение `xxh: config: …` (FR-010); ошибка использования clap — код 2.

## Ключи

- **C-G1**: ключ — путь через точку по именам TOML: `default_shell`,
  `container.runtime`, `hosts.web.cleanup`, `plugins.neovim.source`. Сегмент с
  точкой или пробелом берётся в кавычки: `hosts."web.example.com".user`.
- **C-G2**: известные ключи и виды значений определяются типами конфига (той же
  схемой, что `nix/config-schema.json`).

## `xxh config validate [FILE] [--strict]`

- **C-G3**: проверяется `FILE`, без него — файл, который прочитал бы вход
  (пользовательский, иначе системный). Файла по умолчанию нет — «no config file,
  built-in defaults apply», код 0. Указанного `FILE` нет — ошибка.
- **C-G4**: ошибка (синтаксис, тип, недопустимое значение, неразборчивый `source`)
  — код 40; сообщение содержит путь, строку и столбец, строку файла с ключом и
  значением и допустимые значения.
- **C-G5**: неизвестный ключ — предупреждение в stderr:
  `warning: <файл>:<строка>: unknown key `<путь>` (did you mean `<ключ>`?)`;
  подсказка — когда есть близкий ключ. Код возврата 0; с `--strict` — 40.
- **C-G6**: успех — `<файл>: ok` в stdout (с числом предупреждений, если есть).

## `xxh config init [--force]`

- **C-G7**: создаёт пользовательский конфиг (и каталог) из шаблона с комментариями;
  печатает путь. Шаблон даёт те же настройки, что отсутствие файла (FR-005).
- **C-G8**: файл существует — ошибка «already exists (use --force)», файл не тронут;
  `--force` перезаписывает обычный файл. Управляемый файл — отказ по C-G15.

## `xxh config get <KEY>`

- **C-G9**: печатает значение из файла: строка — как есть, число — числом, список —
  по элементу на строку. Ключ известен, но не задан — ошибка «is not set» с
  умолчанием, если оно есть. Таблица (`hosts.web`) — ошибка с перечнем её ключей.

## `xxh config set <KEY> <VALUE>` / `xxh config unset <KEY>`

- **C-G10**: `set` приводит `VALUE` к виду ключа: целое; список — через запятую
  (пустая строка — пустой список); перечисление — один из вариантов; строка — как
  есть. Недостающие таблицы создаются; файла нет — создаётся с одним этим ключом.
- **C-G11**: остальное содержимое файла — комментарии, порядок, форматирование —
  сохраняется побайтно, кроме изменённой строки (SC-003).
- **C-G12**: неизвестный ключ (с подсказкой), значение не того вида или не из
  допустимых, ключ-таблица — ошибка, файл не меняется (FR-007).
- **C-G13**: `unset` удаляет ключ; ставшая пустой таблица хоста удаляется. Ключ не
  задан — успех без изменений. `unset hosts.web` удаляет таблицу целиком.
- **C-G14**: запись атомарна; `set`/`unset` печатают `<key> = <value>` /
  `<key> unset`.
- **C-G15**: конфиг — симлинк, либо файл или каталог недоступны для записи —
  отказ до любых изменений: «<путь> is managed elsewhere (…) — change it at its
  source» (FR-009). Относится к `set`, `unset`, `edit`, `init --force`,
  `plugin enable|disable`.

## `xxh config edit`

- **C-G16**: редактор — `$VISUAL`, иначе `$EDITOR`; не заданы — ошибка «set
  $EDITOR». Редактируется копия; конфига нет — копия шаблона `init`.
- **C-G17**: после выхода редактора копия проверяется как `validate`. Без ошибок —
  становится конфигом (`saved <путь>`; без изменений — `unchanged`). С ошибкой —
  ошибка показана; stdin — терминал: вопрос `edit again? [Y/n]`; ответ «нет» или
  stdin не терминал — конфиг прежний, копия удалена, код 40.
- **C-G18**: редактор завершился с ошибкой — конфиг прежний, код 40.

## Прочее

- **C-G19**: `xxh plugin enable|disable` меняют `enabled_plugins` той же правкой:
  комментарии и остальное содержимое сохраняются.
- **C-G20**: дополнение: `config get|set|unset <Tab>` — известные ключи (с именами
  хостов, плагинов и шеллов из конфига).
