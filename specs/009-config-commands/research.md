# Research: команды работы с конфигурацией

## R1. Откуда знать ключи

- **Decision**: модель ключей строится из `schemars::schema_for!(Config)` во время
  работы: путь `hosts.<имя>.cleanup` → вид значения (строка, целое, список строк,
  перечисление с вариантами, таблица). `$ref`, `anyOf` с `null` и
  `additionalProperties` (хосты, плагины, шеллы) разворачиваются.
- **Rationale**: типы `Config` — единственный источник истины (Принцип XI); новая
  настройка автоматически становится известна `validate`, `set` и дополнению.
- **Alternatives**: таблица ключей руками — расходится с типами.

## R2. Проверка

- **Decision**: два прохода по тексту. (1) Разбор в `Config` — тот же, что при
  входе; его ошибка уже содержит строку, столбец, фрагмент файла и допустимые
  варианты. (2) Обход документа `toml_edit` против модели ключей: неизвестный ключ —
  предупреждение со строкой и ближайшим известным ключом (расстояние Левенштейна
  ≤ 2 или ≤ трети длины). (3) В CLI — строки `source` в `[plugins.*]` / `[shells.*]`
  разбираются как при `plugin add`; неразборчивая — ошибка.
- Предупреждения не меняют код возврата; `--strict` делает их ошибкой (CI).
- **Rationale**: SC-001 — всё, на чём упал бы вход из-за конфига, ловится тем же
  кодом; отсутствие установленного плагина — это уже `xxh doctor` (006).

## R3. Изменение значений

- **Decision**: `toml_edit::DocumentMut`: существующее значение заменяется на месте
  (с сохранением его комментариев), недостающие таблицы создаются. Значение из
  командной строки приводится к виду ключа: целое разбирается, список — через
  запятую, перечисление сверяется с вариантами. Перед записью результат проходит
  проход (1); при ошибке файл не меняется. Запись — временный файл рядом и rename.
- Имя хоста с точкой задаётся в кавычках: `hosts."web.example.com".user`.
- **Rationale**: FR-007, SC-003.

## R4. Управляемый файл

- **Decision**: если конфиг — симлинк (Home Manager кладёт симлинк в `/nix/store`)
  или его каталог/файл недоступен для записи, `set`, `unset`, `edit`, `init --force`
  отказывают: файл управляется извне, менять его нужно в источнике. Проверка — до
  любых изменений.
- **Rationale**: FR-009; запись «сквозь» симлинк либо упала бы невнятно, либо
  подменила бы управляемый файл обычным.

## R5. `init`

- **Decision**: шаблон — константа в `xxh-config`: активные строки со значениями по
  умолчанию и комментарий к каждой, закомментированные примеры `[hosts.*]`,
  `[plugins.*]`, `[shells.*]`. Unit-тест: шаблон разбирается в `Config::default()`,
  проходит проверку без предупреждений и упоминает каждый ключ верхнего уровня и
  `HostOverride` из схемы. Существующий файл — отказ; `--force` перезаписывает.
- **Rationale**: FR-004, FR-005; тест не даёт шаблону отстать от типов.

## R6. `edit`

- **Decision**: редактор — `$VISUAL`, затем `$EDITOR` (строка делится по пробелам на
  программу и аргументы); не задан — ошибка с подсказкой. Редактируется копия рядом
  с конфигом (нет конфига — шаблон `init`); после выхода редактора копия
  проверяется: ошибок нет — атомарно заменяет конфиг; есть — ошибка показана и при
  интерактивном stdin задаётся вопрос «править снова?», иначе (или при отказе)
  конфиг остаётся прежним, копия удаляется, код 40. Без изменений — «unchanged».
- **Rationale**: FR-008; неверный файл никогда не становится конфигом.

## R7. `plugin enable` / `disable`

- **Decision**: переводятся на ту же правку (`enabled_plugins` как список), вместо
  `Config::save`, который пересоздавал файл и терял комментарии.
- **Rationale**: иначе конфиг из `init` терял бы комментарии при первом же
  `plugin enable` (SC-003 по смыслу); управляемый файл получает то же понятное
  объяснение (FR-009).

## R8. Дополнение

- Ключи для `config get|set|unset` предлагаются из модели ключей (с именами хостов,
  плагинов и шеллов из текущего конфига).
