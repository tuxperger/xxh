# Research: перенос личных файлов без плагина

## R1. Как программа видит файл

- **Decision**: окружением сессии, без записи в `$HOME` цели и без подмены `HOME`:
  - имя под `.config/` — все такие записи лежат в одном дереве, на которое
    указывает `XDG_CONFIG_HOME`;
  - известное имя — переменная самой программы (таблица в контракте, C-F6);
  - любое имя с `env = "VAR"` — переменная получает путь доставленной копии;
  - иначе — предупреждение, запись не доставляется: показать её программе нечем.
- **Rationale**: Принцип I и допущение спеки. Подмена `HOME` прятала бы от
  пользователя всё, что есть на цели (ключи, историю), и меняла бы поведение
  программ, которые пишут в домашний каталог.
- **Следствие**: при записях под `.config/` собственный `~/.config` цели в сессии
  программам не виден (он не изменяется). Задокументировано.

## R2. Единицы доставки

- **Decision**: каждая запись вне `.config/` — свой компонент; все записи под
  `.config/` — один компонент (`files .config`).
- **Rationale**: `XDG_CONFIG_HOME` — один каталог. Собрать его на цели из
  нескольких компонентов можно только ссылками или копированием, а `ln` и `cp` не
  входят в контракт хоста (README: `sh`, `cat`, `mkdir`, `chmod`, `tar`, `gzip`);
  симлинки внутри компонентов не поддерживает ни адресация, ни проверка
  целостности (014). Расширять контракт хоста ради гранулярности — хуже, чем
  передать заново сжатый каталог настроек.
- **Alternatives**: «вид» из симлинков в каталоге сессии — требует `ln`, отдельной
  очистки и согласования с параллельными сессиями; отклонено.

## R3. Сборка компонента

- **Decision**: запись копируется в промежуточный каталог клиента
  (`<stage>/f/<имя>` или `<stage>/.config/…`) вместе с `env.sh`; компонент
  адресуется по дереву и пакуется, только если его нет на цели (как плагины).
  Права файлов сохраняются копированием. Симлинк внутри объявленного каталога
  разыменовывается, только если ведёт внутрь этого каталога; иначе пропускается с
  предупреждением. Промежуточный каталог живёт до конца команды.
- **Rationale**: FR-006, FR-007, edge case про симлинки; общий код адресации.

## R4. Секреты

- **Decision**: запись считается похожей на секрет, если имя файла — известное
  (`id_rsa`, `id_ed25519`, `id_ecdsa`, `id_dsa`, `.netrc`, `.pgpass`,
  `.git-credentials`, `credentials`, `.env`, `*.pem`, `*.key`, `*.kdbx`,
  содержит `token` или `secret`), каталог — `.ssh`, `.gnupg`, `.aws`, либо файл
  начинается с PEM-заголовка приватного ключа. Для каталога проверяется каждый
  файл. Такая запись не доставляется; предупреждение называет файл и ключ
  `secret = true`, который разрешает доставку именно этой записи.
- **Rationale**: FR-008. Ошибиться в сторону отказа безопаснее; обход — одна строка.

## R5. Приоритет

- **Decision**: `[hosts.<имя>.files]` сливается с `[files]` по имени записи:
  запись хоста заменяет одноимённую глобальную и добавляет новые. Запись хоста
  `"<имя>" = false` исключает глобальную для этого хоста.
- **Rationale**: US2 «переопределяет или дополняет»; списки плагинов заменяются
  целиком, но для словаря слияние по ключу — ожидаемое поведение.

## R6. Проверка объявления

- **Decision**: имя — относительный путь без `..`, пустых сегментов и символов,
  значимых для `sh` в двойных кавычках (`"`, `` ` ``, `$`, `\`, перевод строки);
  `env` — `[A-Za-z_][A-Za-z0-9_]*`. Нарушение — ошибка класса config до
  подключения. `~/` в источнике — домашний каталог клиента.
- **Rationale**: имена подставляются в `env.sh`; Принцип V.

## R7. Предупреждения

- До подключения, в stderr, по строке на запись: источник отсутствует (FR-009);
  похоже на секрет; больше 10 МиБ; нет способа показать программе; симлинк наружу.
  Показываются и при тихом режиме одной команды (как notes).

## R8. Генераторы

- Модули Home Manager/NixOS получают `files` и `hosts.<имя>.files` того же вида
  (строка или `{ source, env, secret }`, для хоста также `false`); схема и round-trip
  обновляются (FR-010).
