# Feature Specification: Перенос личных файлов без плагина

**Feature Branch**: `010-dotfiles-delivery`

**Created**: 2026-10-01

**Status**: Implemented

**Priority**: P2

**Summary**: Перечислить в конфиге свои dotfiles — и они окажутся на цели в сессии, без оформления плагина

**Input**: User description: "Проброс dotfiles без плагина: секция в конфиге вида `[files] \".gitconfig\" = \"~/.gitconfig\"`; файлы доставляются как content-addressed компоненты. Оборачивать пару конфигов в плагин с plugin.toml слишком тяжело."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Свои конфиги на цели (Priority: P1)

Пользователь перечисляет в конфиге несколько личных файлов (настройки git, редактора,
tmux). В сессии на любой цели программы видят эти файлы как обычные пользовательские
конфиги; после выхода их нет.

**Why this priority**: личное окружение — это не только шелл; для двух-трёх файлов
писать плагин несоразмерно.

**Independent Test**: объявить файл в конфиге, войти, убедиться, что программа читает
его настройки; выйти и убедиться, что файла на цели нет, а собственные файлы цели не
тронуты.

**Acceptance Scenarios**:

1. **Given** в конфиге объявлен файл, **When** пользователь входит на цель, **Then** в
   сессии программа, читающая этот файл из домашнего каталога, получает содержимое
   пользователя.
2. **Given** на цели уже есть свой файл с тем же именем, **When** сессия идёт и после
   её завершения, **Then** файл цели не изменён и не удалён.
3. **Given** сессия без `--keep` завершена, **When** проверяется цель, **Then**
   доставленных файлов на ней нет.
4. **Given** объявлен каталог, **When** пользователь входит, **Then** каталог доставлен
   целиком с сохранением структуры.

---

### User Story 2 - Разные наборы для разных хостов (Priority: P2)

Пользователь задаёт общий набор файлов и переопределяет или дополняет его для
отдельных хостов.

**Why this priority**: на рабочих и личных машинах нужны разные настройки (например,
идентичность git).

**Independent Test**: для хоста `web` объявлен другой файл; `xxh config show --host web`
и содержимое в сессии это подтверждают.

**Acceptance Scenarios**:

1. **Given** глобальный набор и переопределение для хоста, **When** пользователь входит
   на этот хост, **Then** действует переопределение; на прочих хостах — глобальный
   набор.

---

### User Story 3 - Не перекачивать неизменившееся (Priority: P2)

При повторном входе в сохранённое окружение неизменившиеся файлы не передаются.

**Why this priority**: каталоги настроек бывают большими; правило экономии трафика
общее для всего окружения.

**Independent Test**: второй вход с `--keep` без изменений файлов сообщает, что ничего
не передано.

**Acceptance Scenarios**:

1. **Given** сохранённое окружение и неизменившиеся файлы, **When** пользователь входит
   повторно, **Then** файлы не передаются.
2. **Given** одна объявленная запись изменена, **When** пользователь входит, **Then** передаётся
   только она.

---

### Edge Cases

- Объявленный файл отсутствует на клиенте — предупреждение, сессия продолжается.
- Файл похож на секрет (приватный ключ, файл с токенами) — не доставляется без явного
  разрешения пользователя для этого файла.
- Программа ищет конфиг только по жёсткому пути в домашнем каталоге и не поддерживает
  перенастройку — поведение документировано, пользователь предупреждён.
- Очень большой каталог — предупреждение о размере до передачи.
- Символические ссылки в объявленном каталоге — не выводят за его пределы.
- Права доступа файлов (в частности, «только владелец») сохраняются.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Пользователь MUST иметь возможность объявить в конфигурации файлы и
  каталоги клиента и то, под каким именем они должны быть видны в сессии.
- **FR-002**: Объявленные файлы MUST быть видны программам в сессии как пользовательские
  конфиги.
- **FR-003**: Собственные файлы цели MUST NOT изменяться, перезаписываться или
  удаляться — ни во время сессии, ни после неё.
- **FR-004**: Доставленные файлы MUST размещаться только внутри каталога окружения xxh и
  MUST удаляться по общим правилам очистки.
- **FR-005**: Набор файлов MUST переопределяться для отдельных хостов по общим правилам
  приоритета конфигурации.
- **FR-006**: Неизменившиеся файлы MUST NOT передаваться повторно в сохранённое
  окружение.
- **FR-007**: Права доступа файлов MUST сохраняться.
- **FR-008**: Файлы, распознанные как секреты, MUST NOT доставляться без явного
  разрешения; содержимое файлов MUST NOT попадать в журналы.
- **FR-009**: Отсутствующий на клиенте файл MUST давать предупреждение и MUST NOT
  прерывать сессию.
- **FR-010**: Возможность MUST быть доступна через канонический файл конфигурации и
  через декларативные генераторы в одинаковом объёме.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Пользователь переносит личный конфиг программы на цель, добавив одну
  строку в конфигурацию.
- **SC-002**: В 100% сценариев собственные файлы цели после сессии побайтно совпадают с
  состоянием до неё.
- **SC-003**: После выхода без `--keep` на цели нет ни одного доставленного файла.
- **SC-004**: Повторный вход без изменений не передаёт ни одного файла.

## Assumptions

- Файлы делаются видимыми через подмену расположения пользовательских конфигов в
  окружении сессии, а не через запись в домашний каталог цели (Принцип I).
- Шаблонизация содержимого файлов под хост — вне рамок.
- Передача переменных окружения — фича 011.
- Программы находят файлы через стандартное расположение пользовательских конфигов
  (`XDG_CONFIG_HOME`) и собственные переменные программ; домашний каталог в сессии не
  подменяется. Для файла, который программа ищет только по жёсткому пути, пользователь
  может назвать переменную сам; иначе файл не доставляется, о чём сообщается.
- Когда доставлены файлы из `.config/`, собственный каталог `.config` цели программам
  в сессии не виден (он не изменяется).
- Единица повторной передачи — объявленная запись. Все записи из `.config/`
  образуют одну единицу: общий каталог нельзя собрать на цели из частей, не расширяя
  требования к цели.
- Запись хоста может исключить глобальную запись для этого хоста.
