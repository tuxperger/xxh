# Research: Lock-файл плагинов и декларативные источники

## R1. Объявление

- **Decision**: `[plugins.<имя>] source = "<строка как у plugin add>"`,
  `[shells.<имя>] source = "…"`. Включение — по-прежнему `enabled_plugins`.
- **Rationale**: одна грамматика источника для CLI, конфига и модуля; объявление и
  включение независимы (плагин можно держать установленным, но выключенным).

## R2. Lock-файл

- **Decision**: `xxh.lock` (TOML) рядом с конфигом; `XXH_LOCK_FILE` переопределяет.
  Запись: `source` (строка из конфига), `revision` (git-коммит, иначе нет), `hash`
  (хеш содержимого реестра для плагинов, `tree_hash` пакета без `dist/` для шеллов).
  Порядок — по имени (BTreeMap), атомарная запись.
- **Rationale**: lock — данные о версиях, а не настройки (FR-011); построчный
  стабильный формат удобен для git (FR-008).

## R3. Пин git

- **Decision**: git-провайдер возвращает ревизию (`git rev-parse HEAD` до удаления
  `.git`); ссылка вида 40-hex ставится `fetch` + `checkout` (а не `--branch`).
  Реестр по-прежнему записывает в индекс исходную ссылку — `plugin update`
  двигается вперёд, а lock-файл держит коммит.

## R4. Сборки плагинов

- **Decision**: `[builds.<os-arch>]` в манифесте плагина (008) — при установке в
  реестр копия пакета получает сборку платформы клиента, распакованную в `dist/`
  (как это делал `fetch.sh` плагина), до вычисления хеша; общий код загрузки
  переезжает в `xxh-plugins::fetch`.
- **Rationale**: без этого git-источник neovim даёт плагин без бинаря.

## R5. Синхронизация

- **Decision**: для каждого объявления: установлено с хешем из lock — ничего;
  запись lock есть — установка по ревизии с проверкой хеша (несовпадение — ошибка
  плагина, остальные продолжаются, код 30); записи нет — установка из источника и
  новая запись. Записи lock без объявления удаляются с сообщением. Lock только для
  чтения (Nix) — изменения печатаются, синхронизация не падает.
- **Rationale**: FR-003..FR-005, US1, Edge Cases.

## R6. Модули Nix

- **Decision**: `plugins.<имя>.source`, `shells.<имя>.source`, `lockFile` (путь →
  `xdg.configFile."xxh/xxh.lock"`), `syncOnActivation` (по умолчанию true):
  `home.activation` запускает `xxh sync` с `git`, `curl`, `openssh`, `nix` в `PATH`;
  ошибка — предупреждение.
