# Research: Программы-плагины из Nix flake

Проверено на клиенте с Nix 2.34 (flakes включены). Открытых NEEDS CLARIFICATION нет.

## R1. Синтаксис источника

- **Decision**: `flake:<ref>[#<attr>]`. Всё после префикса до первого `#` — ссылка на
  flake в любой форме, понятной `nix` (`github:o/r`, `github:o/r/ветка`,
  `git+https://…`, `git+file://…`, `path:/…`, `/abs`, `./rel`); после `#` — путь
  атрибута; без `#` — `default`. Относительные пути и `~` приводятся к абсолютным
  при разборе, чтобы `plugin update` работал из любого каталога.
- **Rationale**: явный префикс не пересекается с существующими формами (FR-003):
  `nixpkgs:` проверяется раньше, git-URL и локальные пути не начинаются с `flake:`.
  `nix build 'ref#attr'` сам ищет `packages.<system>.<attr>` и
  `legacyPackages.<system>.<attr>`, поэтому `flake:github:NixOS/nixpkgs#pkgsStatic.ripgrep`
  работает без особой поддержки.
- **Alternatives**: распознавать `github:…`/`git+…` без префикса — конфликтует с
  разбором git-URL и ломает FR-003; отдельная подкоманда `plugin add-flake` —
  расходится с единым `plugin add`.

## R2. Фиксация ревизии

- **Decision**: `nix flake metadata --json <ref>`; поле `url` — зафиксированная
  ссылка (`…?ref=…&rev=<sha>` для git/github), поле `revision` — ревизия. Источник
  считается зафиксированным, только если `revision` непуст. В реестр пишутся
  `locked_url` и `revision`; сборка идёт по `locked_url`.
- **Rationale**: проверено: для git-репозитория `url` содержит `rev`, для грязного
  дерева `revision` = null и появляется `dirtyRevision`, для `path:` есть только
  `narHash`. Ссылка с `narHash` формально «зафиксирована», но при любом изменении
  каталога перестаёт собираться — это не воспроизводимость, а поломка, поэтому
  `path:` и грязные деревья считаются незафиксированными и дают предупреждение
  (FR-018).
- **Alternatives**: хранить `flake.lock`-подобный файл рядом с конфигом — это фича
  013; фиксировать по `narHash` — см. выше.

## R3. Сборка и доверие

- **Decision**: `nix build <locked|ref>#<attr> --no-link --print-out-paths --option
  accept-flake-config false`. Тот же `--option` — у `metadata` и `eval`.
- **Rationale**: `--no-link` не оставляет `result` у пользователя; `accept-flake-config
  false` запрещает flake подмешивать свои substituters и ключи (FR-023) и исключает
  интерактивный вопрос. Сборка идёт в песочнице Nix. Повторный вызов для уже
  собранного выхода — только вычисление (секунды), что закрывает FR-019/SC-007 без
  собственного кеша сборок.
- **Alternatives**: `--impure --expr` с подстановкой `pkgsStatic` — ломает чистоту
  вычисления и не работает для произвольных flake.

## R4. Форма выхода

- **Decision**: если в корне выхода есть `plugin.toml` — выход копируется целиком и
  используется как плагин (FR-005). Иначе, если есть `bin/` с файлами — берётся
  `bin/`, генерируются `plugin.toml` и `env.sh` (FR-006). Иначе — ошибка `BadOutput`
  (FR-007).
- **Rationale**: два осмысленных случая из запроса; манифест имеет приоритет, потому
  что автор явно выразил намерение.
- **Alternatives**: требовать манифест всегда — убивает сценарий «просто программа»;
  копировать весь выход программы (`share/`, `lib/`) — тянет мегабайты и пути в
  `/nix/store`.

## R5. Самодостаточность и платформа

- **Decision**: расширить существующий `audit_static`: для каждого файла пакета —
  ELF с `PT_INTERP` отклоняется (как сейчас); исполняемый текстовый файл с shebang в
  `/nix/store/` отклоняется; из заголовков ELF читается `e_machine` (62 → x86_64,
  183 → aarch64, 40 → armv7l). Все ELF пакета обязаны быть одной архитектуры.
  Обёрнутая программа получает `targets = ["linux/<arch>"]`. Готовому плагину с ELF и
  без `targets` в манифесте провайдер добавляет `targets` (через `toml::Table`, с
  сохранением неизвестных полей); явные `targets` автора не трогаются.
- **Rationale**: архитектура берётся из самого артефакта, а не из системы клиента —
  так корректно обрабатывается выход flake, кросс-собранный под другую платформу
  (допущение спеки). Сессия уже пропускает плагин, чьи `targets` не подходят цели, с
  сообщением (`session.rs`, C-M5) — FR-012 выполняется существующим кодом. Скрипты
  Nix почти всегда имеют shebang в `/nix/store` и на цели не запустятся — ловим это
  на клиенте (SC-005).
- **Alternatives**: брать платформу из `builtins.currentSystem` — неверно для
  кросс-выходов; не проверять shebang — отказ на хосте вместо клиента.

## R6. Данные времени исполнения

- **Decision**: для обёрнутой программы — тот же набор, что у nixpkgs-источника
  (terminfo из `ncurses`, CA-бандл из `cacert` зафиксированного nixpkgs, подключение
  через `env.sh`); код выносится в общую функцию. Для готового плагина — ничего не
  добавляется.
- **Rationale**: FR-011 требует паритета; готовый плагин — ответственность автора.

## R7. Имя и версия обёрнутой программы

- **Decision**: имя — `--name`, иначе последний сегмент `attr`, если он не `default`,
  иначе последний сегмент ссылки (без `?query`, `.git`, завершающих `/`); приводится
  к `[a-z0-9-]`. Версия — `nix eval --raw <ref>#<attr>.version`; если это не semver —
  дополняется `.0`; иначе `0.1.0`. Для готового плагина `--name` — ошибка (имя задаёт
  манифест).
- **Rationale**: детерминированно и предсказуемо (FR-008); `pkgsStatic.ripgrep` →
  `ripgrep`. Префикс вида `nix-` не нужен — конфликт имён ловится явно (R8).

## R8. Конфликт имён

- **Decision**: при записи в реестр: если имя занято плагином другого происхождения и
  хотя бы одна сторона — flake, установка отклоняется (`NameConflict`) с подсказкой
  `--name` или `plugin remove`. Одинаковое происхождение (та же ссылка и выход) —
  обновление на месте. Для пар git/local поведение прежнее.
- **Rationale**: FR-009 без изменения поведения существующих источников (FR-003,
  объём фичи 001).

## R9. Контракт источника и реестр

- **Decision**: `FetchedPackage` получает `resolved: Option<SourceSpec>`; реестр
  сохраняет `resolved`, если он есть, иначе исходную спеку. `Registry::update`
  передаёт провайдеру спеку со снятым пином (`SourceSpec::unpinned()`), обычная
  установка спеки с пином собирает ровно зафиксированную ревизию.
- **Rationale**: минимальное расширение C-S5; git/local/nixpkgs возвращают `None`.
  Старые `index.toml` читаются без миграции — новый вариант аддитивен.
- **Alternatives**: отдельный lock-файл — фича 013.

## R10. Учётные данные в ссылке

- **Decision**: функция `redact_ref` заменяет `user:secret@` в URL на `<redacted>@` и
  значения параметров `access_token`/`token` на `<redacted>`; применяется в
  `describe()`, во всех сообщениях об ошибках и к хвосту stderr сборки. В
  `index.toml` ссылка хранится как есть (без неё невозможен `update`) — файл лежит в
  каталоге данных пользователя.
- **Rationale**: FR-024; рекомендуемый способ аутентификации — `netrc`/`access-tokens`
  самого Nix, а не токен в ссылке (отражается в README).

## R11. Тестовые flake

- **Decision**: интеграционные тесты генерируют локальный flake во временном
  git-репозитории с входом `nixpkgs` на тот же пин, что у nixpkgs-источника
  (`XXH_NIXPKGS_PIN`): выход-программа — `pkgsStatic.ripgrep`; выход-плагин —
  `runCommand` с `plugin.toml` + `env.sh`; динамический выход — `hello`.
- **Rationale**: локальный git-репозиторий даёт настоящую ревизию и возможность
  сделать второй коммит (сценарий пина/обновления) без сети сверх nixpkgs;
  `pkgsStatic.ripgrep` уже собирается существующим тестом — общий кеш.
