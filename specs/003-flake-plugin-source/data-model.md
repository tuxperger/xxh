# Data Model: Программы-плагины из Nix flake

## SourceSpec::Flake (данные источника; хранится в `index.toml`)

| Поле | Тип | Обяз. | Смысл |
|---|---|---|---|
| `reference` | строка | да | Ссылка на flake, как ввёл пользователь (пути — абсолютные) |
| `attr` | строка | да | Путь атрибута выхода; по умолчанию `default` |
| `locked_url` | строка | нет | Зафиксированная ссылка (`url` из метаданных); есть только у зафиксированного источника |
| `revision` | строка | нет | Ревизия источника; отсутствует у незафиксированного (локальный каталог, грязное дерево) |
| `name` | строка | нет | Имя плагина, заданное `--name` |

Сериализация: `type = "flake"`; необязательные поля опускаются. Старые индексы без
этого варианта читаются без изменений.

**Правила**

- `reference` непуста; `attr` непуст (пустой фрагмент `#` → ошибка разбора).
- Зафиксирован ⇔ `revision` присутствует; тогда присутствует и `locked_url`.
- Происхождение (`same_origin`) — пара (`reference`, `attr`); пин и имя в сравнение не
  входят.
- `unpinned()` — та же спека без `locked_url` и `revision`.
- `describe()` — `flake:<reference>#<attr>` с отредактированными учётными данными;
  эту форму можно подать обратно в `plugin add`.

**Переходы состояния**

```
add (ref, attr)          ──► metadata ──► pinned(locked_url, revision)   [есть revision]
                                      └─► unpinned + предупреждение      [нет revision]
install(pinned)          ──► сборка locked_url, пин не меняется
update(name)             ──► unpinned() ──► metadata ──► новый пин (или тот же)
remove(name)             ──► запись удалена из индекса
```

## FetchedPackage (результат провайдера) — расширение

| Поле | Тип | Смысл |
|---|---|---|
| `resolved` | `Option<SourceSpec>` | Спека, которую реестр должен сохранить вместо исходной (с пином). `None` — сохранить исходную |

## IndexEntry (реестр) — без изменения формы

`source` теперь может быть `Flake`. Новое правило записи: имя, занятое плагином
другого происхождения, при участии flake-источника с любой стороны → `NameConflict`.

## Пакет, порождённый провайдером

**Готовый плагин** (в выходе есть `plugin.toml`): содержимое выхода как есть; если в
пакете есть ELF и в манифесте нет `targets` — добавляется `targets = ["linux/<arch>"]`.

**Обёрнутая программа** (в выходе есть `bin/`):

```text
plugin.toml     name, version, api_version = "1.0.0", targets = ["linux/<arch>"]
env.sh          PATH=$XXH_COMPONENT_DIR/bin:$PATH; SSL_CERT_FILE; TERMINFO
bin/            исполняемые файлы выхода (симлинки разыменованы)
etc/ssl/certs/ca-bundle.crt
share/terminfo/
```

`<arch>` — из `e_machine` ELF-файлов пакета: `x86_64` | `aarch64` | `armv7l`. Пакет без
ELF (только самодостаточные скрипты) получает `targets = ["linux"]`.

## Результат аудита самодостаточности

| Поле | Смысл |
|---|---|
| `arch` | Единая архитектура всех ELF пакета либо «нет ELF» |
| нарушения | Список файлов: динамический ELF, shebang в `/nix/store`, смешанные архитектуры, неизвестная архитектура |

Любое нарушение → установка отклонена, в реестр и клиентский кеш ничего не записано.

## Клиентский кеш пакетов

Каталог `~/.local/share/xxh/nix-cache/<ключ>/` (переопределение `XXH_NIX_CACHE_DIR`),
ключ = blake3(путь результата сборки | форма | имя). Запись появляется атомарно
(staging → rename) только после успешного аудита.
