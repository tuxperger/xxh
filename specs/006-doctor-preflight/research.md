# Research: Диагностика клиента и цели до входа

## R1. Что спросить у цели, ничего не записав

- **Decision**: новая подкоманда bootstrap `probe`, запускаемая потоком
  (`sh -s -- probe`), плюс уже существующие `detect` и `status` (005). `probe`
  сообщает пути обязательных и желательных утилит, корень, куда лёг бы вход, и
  свободное место там.
- **Rationale**: тот же приём, что у `detect`/`status`, — работает во всех
  транспортах и не расширяет контракт хоста.

## R2. Корень входа без `mkdir`

- **Decision**: повторить порядок `xxh_resolve_root` ($HOME → $TMPDIR → /tmp) с
  проверками вместо создания: существующий `<base>/.xxh` с правом записи —
  `existing`; иначе каталог `<base>` с правом записи — `new`; иначе следующий.
  Ничего не подошло — `root -`.
- **Rationale**: вход делает `mkdir -p <base>/.xxh && [ -w ]`; без записи этому
  соответствует право записи в существующий каталог или в его родителя.
- **Alternatives**: попытаться создать и удалить — запрещено FR-005.

## R3. Место

- **Decision**: свободное — `df -Pk <каталог>` (POSIX-формат, 4-е поле второй
  строки) для существующего корня или для `<base>` нового. Требуемое — сумма
  распакованных размеров компонентов плана, адресов которых нет в этом корне
  (ответ `status`). Размер компонента-каталога — сумма длин файлов дерева;
  сгенерированного (готовый архив) — длина архива (крошечные). Свободного меньше
  требуемого — провал с числами; нет `df` — предупреждение.
- **Rationale**: распаковка идёт во временный каталог рядом и переименовывается —
  пиковый объём равен размеру дерева.

## R4. «Нет пакета» против «нет сборки под платформу»

- **Decision**: `shellpkg::lookup(shell, platform)` → `Found(pkg)` /
  `NoBuild { available }` / `NotInstalled`; `find` остаётся обёрткой. В плане
  входа `NoBuild` при наличии шелла на цели даёт заметку («нет сборки … для
  linux-aarch64; используется zsh цели»), при отсутствии — `ShellError::NoBuild` с
  перечнем имеющихся сборок и действием (FR-009). CLI печатает заметки плана в
  stderr всегда — это не стадии, а предупреждения.
- **Rationale**: раньше этот случай был только в debug-логе (Input спеки).

## R5. Проверки клиента

- **Decision**: конфиг — загрузка тем же `config::load`; плагины — каждый включённый
  ищется в реестре по имени (нет — провал с действием), затем резолвер порядка;
  пакет шелла без цели — перечень сборок (`sh` проходит всегда); источники — `git`,
  при сборке с `nix-source` — `nix` в `PATH` (нет — предупреждение); рантаймы —
  `docker`/`podman` в `PATH` (нет ни одного — предупреждение).
- **Rationale**: поиск в `PATH` не запускает ничего и не требует сети (US2 —
  «без сети»).

## R6. Код возврата и формат

- **Decision**: `0` — нет провалов; `1` — есть провал; цель недостижима — `10`, но
  проверки клиента и проваленная проверка `connect` выводятся. `--json` — один
  объект (contracts/cli-doctor.md).
- **Rationale**: FR-007; скрипт отличает «цель недоступна» от «цель не годится».
