# Contract: автодополнение и справочные страницы (C-K*)

## `xxh completions <shell>`

- **C-K1**: `<shell>` — `bash`, `zsh` или `fish`. В stdout — скрипт, код 0. Скрипт
  не содержит абсолютных путей и ничего, что зависит от версии xxh.
- **C-K2**: другое имя или его отсутствие — ошибка использования, код 2, в сообщении
  перечислены поддерживаемые шеллы. Ничего не печатается в stdout.
- **C-K3**: подключение — одна строка:

  ```sh
  eval "$(xxh completions bash)"        # ~/.bashrc
  source <(xxh completions zsh)         # ~/.zshrc, после compinit
  xxh completions fish | source         # ~/.config/fish/config.fish
  ```

  zsh-скрипт начинается с `#compdef xxh` и работает также как файл `_xxh` в `fpath`.

## `xxh __complete <shell> <index> -- <слова…>` (скрытая)

Вызывается только заглушками; в `--help` и на man-страницах отсутствует.

- **C-K4**: `<слова…>` — командная строка по словам, начиная с имени команды;
  `<index>` — номер дополняемого слова (с нуля). Ответ — по строке на кандидата:
  `значение` или `значение<TAB>описание`.
- **C-K5**: код возврата всегда 0, stderr пуст — при любых аргументах, нечитаемом
  конфиге, отсутствии реестра, недоступном рантайме (FR-006). Нечего предложить —
  пустой вывод.
- **C-K6**: подкоманды, флаги и перечислимые значения флагов (`--transport`,
  `--runtime`, `completions <shell>`) берутся из того же описания CLI, что и разбор
  аргументов; глобальные флаги предлагаются и после подкоманды (FR-002).
- **C-K7**: цель (первый позиционный аргумент без подкоманды и `target` у `status`,
  `doctor`, `clean`):
  - схемы `docker:`, `podman:`, `container:`, `ssh:`;
  - ключи `[hosts.*]` конфига xxh;
  - алиасы `Host` из `~/.ssh/config` и файлов по `Include`; имена с `*`, `?`, `!`
    не предлагаются;
  - `user@пре` и `ssh:пре` дополняются по `пре`, префикс сохраняется;
  - повторы убраны, порядок — по алфавиту. В первой позиции цели идут вместе с
    подкомандами.
- **C-K8**: слово `docker:пре` / `podman:пре` / `container:пре` — имена запущенных
  контейнеров рантайма (для `container:` — по `container.runtime`, при `auto`
  первый найденный из docker, podman), со схемой в значении.
- **C-K9**: рантайм вызывается только на чтение (`ps`), не дольше 150 мс; при
  превышении, ошибке, отсутствии бинаря или нелокальном `DOCKER_HOST` /
  `CONTAINER_HOST` — пустой список. Сетевых обращений дополнение не делает, на
  цели ничего не исполняет.
- **C-K10**: имена плагинов и шеллов:

  | Аргумент | Кандидаты |
  | --- | --- |
  | `plugin enable <name>` | установленные и не включённые |
  | `plugin disable <name>` | включённые |
  | `plugin remove\|update <name>` | установленные |
  | `shell fetch\|update\|remove <shell>`, `--shell` | установленные пакеты шеллов |

- **C-K11**: `-i/--identity` и `man --dir` дополняются путями файловой системы;
  после `--` и для значения `-c` кандидатов нет.
- **C-K12**: кандидат, после которого ввод продолжается (`docker:`, `user@`,
  каталог), подставляется без пробела в конце.

## `xxh man [--dir <каталог>]`

- **C-K13**: без `--dir` — страница `xxh(1)` в формате roff в stdout
  (`xxh man | man -l -`).
- **C-K14**: с `--dir` — в каталог (создаётся при отсутствии) пишутся `xxh.1` и по
  странице на каждую видимую подкоманду любого уровня, имя — путь команды через
  дефис: `xxh-plugin.1`, `xxh-plugin-add.1`. Существующие файлы перезаписываются.
- **C-K15**: страницы строятся из описания CLI: имена, описания и флаги совпадают со
  встроенной справкой (SC-004). `xxh(1)` дополнительно содержит разделы
  EXIT STATUS (0, 1, 2, 10, 20, 30, 40, 50 с классами ошибок) и FILES (конфиг,
  lock-файл, реестр плагинов, пакеты шеллов).
- **C-K16**: каталог нельзя создать или записать — сообщение `xxh: man: …` с путём,
  код 2.

## Поставка

- **C-K17**: пакет `xxh` из flake содержит
  `share/bash-completion/completions/xxh.bash`, `share/zsh/site-functions/_xxh`,
  `share/fish/vendor_completions.d/xxh.fish` и `share/man/man1/xxh*.1`;
  статические пакеты — те же файлы. Модули Home Manager и NixOS ставят пакет в
  профиль — дополнение и `man xxh` работают без ручных действий.
