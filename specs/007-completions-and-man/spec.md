# Feature Specification: Автодополнение и справочные страницы

**Feature Branch**: `007-completions-and-man`

**Created**: 2026-10-01

**Status**: Implemented

**Priority**: P2

**Summary**: Автодополнение команд, флагов, хостов и плагинов в шелле пользователя и man-страницы для xxh

**Input**: User description: "`xxh completions <shell>` и man-страница: генерация скриптов автодополнения для популярных шеллов и справочных страниц."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Автодополнение в своём шелле (Priority: P1)

Пользователь подключает автодополнение одной строкой в конфиге шелла и дальше дополняет
клавишей Tab подкоманды, флаги и их значения.

**Why this priority**: инструмент вызывают десятки раз в день; дополнение — базовое
ожидание от CLI.

**Independent Test**: сгенерировать скрипт для шелла, подключить, убедиться, что
подкоманды и флаги дополняются.

**Acceptance Scenarios**:

1. **Given** поддерживаемый шелл, **When** пользователь выполняет
   `xxh completions <шелл>`, **Then** в стандартный вывод выдаётся готовый к подключению
   скрипт автодополнения.
2. **Given** подключённое автодополнение, **When** пользователь дополняет подкоманду или
   флаг, **Then** предлагаются актуальные для этой версии варианты.
3. **Given** неподдерживаемое имя шелла, **When** выполняется команда, **Then** ошибка
   использования перечисляет поддерживаемые шеллы.

---

### User Story 2 - Дополнение целей и плагинов (Priority: P2)

При вводе цели предлагаются хосты из пользовательской конфигурации SSH и из конфига
xxh, а также запущенные контейнеры; в командах управления плагинами — имена
установленных плагинов.

**Why this priority**: именно эти значения вводятся чаще всего и длиннее всего.

**Independent Test**: при наличии хоста `web` в конфигурации ввод `xxh w<Tab>`
дополняется до `web`; `xxh plugin enable <Tab>` предлагает установленные плагины.

**Acceptance Scenarios**:

1. **Given** хосты в конфигурации SSH и секции хостов конфига xxh, **When** дополняется
   цель, **Then** предлагаются эти хосты.
2. **Given** префикс контейнерной цели, **When** дополняется ссылка, **Then**
   предлагаются запущенные контейнеры доступного рантайма.
3. **Given** установленные плагины, **When** дополняется аргумент команды управления
   плагином, **Then** предлагаются подходящие по состоянию имена.

---

### User Story 3 - Справочные страницы (Priority: P3)

Пользователь читает `man xxh` и страницы подкоманд без доступа в сеть.

**Why this priority**: полезно, но встроенная справка уже покрывает основную потребность.

**Independent Test**: сгенерированные страницы открываются стандартным просмотрщиком и
описывают все подкоманды и флаги.

**Acceptance Scenarios**:

1. **Given** установленный пакет xxh, **When** пользователь вызывает справочную
   страницу, **Then** она описывает все команды, флаги, коды возврата и расположение
   конфигурации.

---

### Edge Cases

- Рантайм контейнеров недоступен — дополнение контейнеров молча даёт пустой список, не
  задерживая ввод.
- Конфигурация SSH содержит шаблоны (`Host *`) — шаблоны не предлагаются как хосты.
- Дополнение не должно выполнять сетевых обращений и заметно задерживать ввод.
- Версия скрипта автодополнения отстала от версии xxh — дополнение деградирует без
  ошибок в шелле.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST генерировать скрипты автодополнения как минимум для bash,
  zsh и fish.
- **FR-002**: Автодополнение MUST покрывать все подкоманды, флаги и перечислимые
  значения флагов.
- **FR-003**: Автодополнение цели MUST предлагать хосты из конфигурации SSH пользователя
  и из конфига xxh, исключая шаблоны.
- **FR-004**: Автодополнение контейнерной цели MUST предлагать запущенные контейнеры.
- **FR-005**: Автодополнение аргументов команд управления плагинами MUST предлагать
  имена установленных плагинов.
- **FR-006**: Динамическое дополнение MUST NOT выполнять сетевых обращений и MUST NOT
  выводить ошибки в терминал пользователя.
- **FR-007**: Система MUST предоставлять справочные страницы для основной команды и
  каждой подкоманды, согласованные со встроенной справкой.
- **FR-008**: Пакеты и модули поставки MUST устанавливать автодополнение и справочные
  страницы без ручных действий.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Подключение автодополнения требует не более одной строки в конфигурации
  шелла.
- **SC-002**: 100% подкоманд и флагов дополняются в каждом поддерживаемом шелле.
- **SC-003**: Варианты дополнения появляются без ощутимой задержки (менее 200 мс).
- **SC-004**: Справочные страницы и встроенная справка не расходятся по составу команд
  и флагов.

## Assumptions

- Автодополнение работает в шелле клиента; дополнение внутри перенесённого шелла на
  цели — забота плагинов этого шелла.
- Поставка через Nix-модули опирается на существующие модули фичи 001.
- Хосты берутся из конфигурации SSH (включая подключаемые ею файлы) и конфига xxh;
  `known_hosts` источником не служит.
- «Без сетевых обращений» для контейнеров обеспечивается так: рантайм, явно
  настроенный на удалённый адрес, не опрашивается; любой опрос ограничен по времени.
  Удалённый контекст рантайма, выбранный иначе, ограничивается только временем.
- Справочные страницы порождает сам инструмент (тем же описанием команд, что и
  встроенная справка), поэтому доступны и при сборке без Nix.
