# Contract: Transport::exec_stream (C-X*)

Расширяет `specs/002-container-targets/contracts/transport-trait-v2.md`.

```rust
/// Run `cmd` without a PTY, with the client's stdin/stdout/stderr attached.
async fn exec_stream(&mut self, cmd: &str) -> Result<i32, TransportError>;
```

- **C-X1**: stdout команды попадает в stdout клиента, stderr — в stderr, побайтно и
  без объединения потоков; реализация не буферизует весь вывод.
- **C-X2**: stdin клиента передаётся команде; по EOF на stdin клиента команда
  получает EOF.
- **C-X3**: результат — код возврата команды; завершение сигналом S → 128 + S;
  неизвестный код → 255.
- **C-X4**: реализация ничего не пишет в stdout/stderr клиента от своего имени.
- **C-X5**: отмена (drop future) освобождает ресурсы: дочерний процесс CLI-бэкенда
  завершается, задачи-форвардеры останавливаются; транспорт остаётся пригодным для
  `exec`.
- **C-X6**: сбой соединения — `TransportError`, как у остальных методов.
- **C-X7**: командная строка и данные потоков не журналируются.

## Session::run_exec

- **C-X8**: команда исполняется после того же prelude, что и интерактивный шелл, под
  тем же trap очистки.
- **C-X9**: перед `exec` pid записывается в `sessions/<sid>.cmd`.
- **C-X10**: при SIGINT/SIGTERM клиента: поток отменяется, на цели выполняется
  `kill -TERM <pid>`, ожидается исчезновение маркера сессии (≤ 5 с), результат —
  128 + номер сигнала.
- **C-X11**: `tty = true` — команда запускается через `open_pty`; C-X10 не
  применяется (сигналы идут через терминал).
