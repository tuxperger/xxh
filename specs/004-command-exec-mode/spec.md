# Feature Specification: Выполнение одной команды в своём окружении

**Feature Branch**: `004-command-exec-mode`

**Created**: 2026-10-01

**Status**: Draft

**Priority**: P1

**Summary**: `xxh <цель> -- команда` выполняет одну команду в перенесённом окружении и возвращает её код — для скриптов и CI

**Input**: User description: "Неинтерактивный режим: `xxh host -- cmd args` — выполнить одну команду в своём окружении на SSH-хосте или в контейнере без интерактивной сессии, с пробросом stdin/stdout/stderr и кода возврата; пригодно для скриптов и CI."

## Clarifications

### Session 2026-10-01

Решения приняты без опроса пользователя (он просил не спрашивать) по коду и
конституции; каждое можно пересмотреть правкой этого раздела.

- Q: Аргументы после `--` исполняются напрямую или через шелл? → A: Напрямую, как
  заданный список аргументов, без повторной интерпретации (FR-006). Для командной
  строки с конвейерами, перенаправлениями и алиасами — отдельный флаг
  `-c/--command <строка>`: строка исполняется выбранным шеллом пользователя (FR-011).
- Q: Куда идут сообщения об этапах в режиме команды? → A: Никуда по умолчанию;
  показываются в потоке ошибок только при `-v` и выше (FR-012). Ошибки xxh
  показываются всегда.
- Q: Что происходит при прерывании (Ctrl-C, SIGTERM)? → A: xxh завершает команду на
  цели, дожидается очистки окружения и возвращает 128 + номер сигнала (FR-013).
- Q: Какой код возврата, если команда на цели убита сигналом или код неизвестен? →
  A: 128 + номер сигнала, если он известен, иначе 255 (FR-004).
- Q: Как отличить код команды от кода ошибки xxh? → A: Ошибке xxh всегда предшествует
  строка `xxh: <класс>: …` в потоке ошибок; код команды передаётся без сообщения
  (FR-010).

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Одна команда вместо сессии (Priority: P1)

Пользователь хочет выполнить на удалённой машине одну команду своими инструментами —
своим шеллом, алиасами, программами из плагинов — и получить результат в свой терминал
или в скрипт, не открывая интерактивную сессию.

**Why this priority**: сегодня инструмент пригоден только для ручной работы; без
неинтерактивного режима его нельзя встроить в скрипты и автоматизацию.

**Independent Test**: выполнить `xxh <цель> -- <команда из плагина>`, сверить вывод и
код возврата, убедиться в чистоте цели после завершения.

**Acceptance Scenarios**:

1. **Given** настроенное окружение с включённым плагином, **When** пользователь
   выполняет `xxh <цель> -- <команда>`, **Then** команда исполняется в его окружении,
   её вывод попадает в стандартный вывод клиента, а код возврата xxh равен коду команды.
2. **Given** команда завершилась с ненулевым кодом, **When** xxh завершается, **Then**
   код возврата xxh совпадает с кодом команды и отличим от кодов ошибок самого xxh.
3. **Given** данные поданы на стандартный ввод xxh, **When** выполняется команда,
   **Then** команда получает эти данные на своём стандартном вводе.
4. **Given** режим без `--keep`, **When** команда завершилась (успешно или нет),
   **Then** на цели не остаётся артефактов окружения.

---

### User Story 2 - Использование в конвейерах (Priority: P2)

Пользователь встраивает xxh в конвейер: вывод команды передаётся следующей программе,
а служебные сообщения xxh в него не попадают.

**Why this priority**: без чистого разделения вывода режим непригоден для обработки
результатов программами.

**Independent Test**: `xxh <цель> -- printf data | wc -c` даёт ровно длину данных.

**Acceptance Scenarios**:

1. **Given** вывод xxh перенаправлен в файл или конвейер, **When** команда пишет в
   стандартный вывод, **Then** там оказывается только вывод команды, байт в байт.
2. **Given** команда пишет в поток ошибок, **When** пользователь перенаправляет потоки
   раздельно, **Then** потоки команды остаются разделёнными.
3. **Given** стандартный ввод не является терминалом, **When** запускается команда,
   **Then** xxh не запрашивает ничего интерактивно и не зависает в ожидании ввода.

---

### Edge Cases

- Команда содержит кавычки, пробелы, спецсимволы шелла — аргументы доходят до цели без
  искажений и повторной интерпретации.
- Пользователь прерывает выполнение (Ctrl-C) — команда на цели завершается, окружение
  вычищается.
- Соединение рвётся во время выполнения — ошибка класса «транспорт», очистка
  выполняется при следующем входе.
- Команде нужен терминал (полноэкранная программа) — пользователь может явно запросить
  выделение терминала.
- Аргумент после `--` пуст — ошибка использования до подключения.
- Код возврата команды совпадает с одним из кодов ошибок xxh (10/20/30/40) — документировано,
  как отличить.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST принимать команду с аргументами после разделителя `--` для
  целей обоих семейств (SSH-хост и контейнер).
- **FR-002**: Команда MUST исполняться в том же окружении, что и интерактивная сессия:
  выбранный шелл, конфигурация, включённые плагины.
- **FR-003**: Стандартные ввод, вывод и поток ошибок команды MUST быть связаны с
  соответствующими потоками клиента; вывод и поток ошибок MUST оставаться раздельными.
- **FR-004**: Код возврата xxh MUST быть равен коду возврата команды, если подключение
  и развёртывание прошли успешно. Если команда завершена сигналом — 128 + номер
  сигнала; если код неизвестен — 255.
- **FR-005**: Служебные сообщения xxh (этапы, предупреждения) MUST NOT попадать в
  стандартный вывод ни при каких настройках.
- **FR-006**: Аргументы команды MUST передаваться на цель без повторной интерпретации.
- **FR-007**: Гарантии очистки MUST быть теми же, что и для интерактивной сессии,
  включая прерывание и сбой.
- **FR-008**: Пользователь MUST иметь возможность явно запросить терминал для команды.
- **FR-009**: В неинтерактивном режиме система MUST NOT запрашивать ввод у
  пользователя; необходимость ввода (пароль, подтверждение ключа хоста) MUST приводить
  к ошибке с объяснением.
- **FR-010**: Сбой самого xxh MUST быть отличим от ненулевого кода команды: ему
  всегда предшествует сообщение `xxh: <класс>: …` в потоке ошибок, а код команды
  передаётся без сообщения.
- **FR-011**: Система MUST принимать командную строку одним аргументом флага
  `-c/--command` и исполнять её выбранным шеллом пользователя; `-c` и аргументы после
  `--` взаимоисключающи.
- **FR-012**: В режиме команды сообщения об этапах MUST NOT выводиться без явного
  запроса подробного режима; сообщения об ошибках xxh выводятся всегда.
- **FR-013**: При прерывании xxh (SIGINT, SIGTERM) команда на цели MUST быть
  завершена, окружение вычищено по общим правилам, а код возврата xxh — 128 + номер
  сигнала.
- **FR-014**: Флаги режима команды MUST отклоняться вместе с подкомандами (`config`,
  `plugin`) и при отсутствии цели — до подключения.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Вывод команды, полученный через xxh, побайтно совпадает с выводом той же
  команды, выполненной на цели напрямую.
- **SC-002**: Код возврата команды доходит до вызывающего скрипта в 100% случаев.
- **SC-003**: После завершения команды цель чиста в 100% сценариев, включая прерывание.
- **SC-004**: При сохранённом окружении (`--keep`) накладные расходы на запуск команды
  не превышают времени подключения плюс одной секунды.

## Assumptions

- Опирается на существующий механизм выполнения команды в подготовленном окружении,
  используемый сегодня только тестами.
- Параллельное выполнение на нескольких целях — отдельная фича (020).
- Потоковая передача больших объёмов через стандартный ввод/вывод допустима; специальная
  передача файлов — отдельная фича (021).
