# Implementation Plan: Выполнение одной команды в своём окружении

**Branch**: `004-command-exec-mode` | **Date**: 2026-10-01 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/004-command-exec-mode/spec.md`

## Summary

`xxh <цель> -- <команда> [аргументы…]` и `xxh <цель> -c '<строка>'` выполняют одну
команду в том же развёрнутом окружении, что и интерактивная сессия, и возвращают её
код. Развёртывание, доставка, кеш и очистка не меняются — меняется только последний
шаг: вместо PTY с шеллом запускается команда, чьи stdin/stdout/stderr напрямую
связаны с потоками клиента.

Для этого в `trait Transport` добавляется один метод — `exec_stream` (команда со
сквозным stdio, без PTY) — и реализуется в трёх бэкендах. `Session` получает
`run_exec`: собирает командную строку (точный список аргументов либо строка для
шелла пользователя), записывает pid команды на цели и, если клиент прерван сигналом,
завершает команду там и дожидается очистки. CLI получает хвостовые аргументы после
`--`, флаги `-c/--command` и `-t/--tty`; сообщения об этапах в режиме команды
молчат без `-v`. Попутно `read_secret` перестаёт читать «пароль» из не-терминала —
иначе он съел бы stdin команды.

## Technical Context

**Language/Version**: Rust 1.85, edition 2024, workspace crates

**Primary Dependencies**: существующие — `tokio` (process, io-std, signal), `russh`,
`clap`, `async-trait`, `libc`. Новых зависимостей нет.

**Storage**: на цели — один дополнительный файл `sessions/<sid>.cmd` (pid команды) в
каталоге окружения, удаляемый общей очисткой

**Testing**: unit — сборка командной строки и экранирование, разбор CLI, отображение
кодов возврата, мок-транспорт; интеграция — реальный бинарь `xxh` против sshd-контейнера
(оба SSH-бэкенда) и против контейнерной цели, с проверкой чистоты

**Target Platform**: клиент Linux/macOS; цели — как у интерактивной сессии

**Project Type**: CLI-инструмент, многокрейтовый workspace

**Performance Goals**: накладные расходы сверх подключения и развёртывания — не более
секунды (SC-004); потоковая передача без буферизации всего вывода в памяти

**Constraints**: stdout клиента содержит только вывод команды, байт в байт; потоки
раздельны; zero-footprint и гарантированная очистка — как у сессии, включая
прерывание; никаких запросов ввода при stdin-не-терминале; секреты не журналируются

**Scale/Scope**: один метод trait + 3 реализации, один метод `Session`, правки
`bootstrap.sh` (одна строка очистки), CLI; три интеграционных теста

## Constitution Check

*GATE: конституция v1.5.0. Проверено до Phase 0 и после Phase 1.*

| Принцип | Как соблюдается | Статус |
|---|---|---|
| I. Zero-footprint | Тот же каталог окружения и тот же trap очистки; файл pid лежит внутри него и удаляется вместе с маркером сессии. Прерывание клиента завершает команду на цели и дожидается очистки | ✅ |
| II. Статический бинарник | Без новых зависимостей | ✅ |
| III. Абстракция транспорта | Новая возможность — метод единого trait; `xxh-core` не знает о семействе; остановка по сигналу выражена через уже существующий `exec` | ✅ |
| IV. Плагины | Не затронуты; команда видит то же окружение плагинов | ✅ |
| V. Безопасность | Аргументы экранируются, а не интерполируются; пароль не читается из не-терминала; командная строка не журналируется выше debug | ✅ |
| VI. Производительность | Развёртывание и кеш те же; вывод потоковый | ✅ |
| VII. Наблюдаемость | Ошибки xxh всегда с классом и кодом 10/20/30/40; код команды — без сообщения; этапы — по `-v` | ✅ |
| VIII. Тестируемость | Интеграция реальным бинарём по обоим семействам транспорта, каждый сценарий с проверкой чистоты, включая прерывание | ✅ |
| IX–XI | Не затронуты (конфиг не меняется) | ✅ |

Гейт пройден, отклонений нет.
