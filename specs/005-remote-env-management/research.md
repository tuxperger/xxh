# Research: Управление сохранённым окружением на цели

## R1. Как говорить с целью, ничего на неё не записав

- **Decision**: новые подкоманды `status`, `clean`, `prune` того же `bootstrap.sh`,
  запускаемого потоком: `sh -s -- status` со скриптом в stdin (как `detect` и `root`).
- **Rationale**: при входе скрипт сначала кладётся в `<root>/boot.sh`, но для `status`
  это уже запись (FR-012), а для `clean` — бессмысленная запись в удаляемый каталог.
  Потоковый запуск работает во всех транспортах (`upload_stream`) и не расширяет
  контракт хоста.
- **Alternatives**: отдельные команды `ls`/`rm` через `exec` — логика размазалась бы по
  клиенту и зависела бы от экранирования путей в каждом транспорте.

## R2. Где искать каталог окружения

- **Decision**: скрипт перебирает `$HOME/.xxh`, `$TMPDIR/.xxh`, `/tmp/.xxh` (тот же
  порядок, что `xxh_resolve_root`), берёт существующие каталоги, принадлежащие
  текущему пользователю (`[ -d ] && [ -O ]`, не симлинк), без повторов. `mkdir` не
  вызывается.
- **Rationale**: вход может положить окружение в любой из трёх (002 C-C12); чужой
  `/tmp/.xxh` не наш (FR-010, «текущего пользователя»). Клиент не передаёт путь —
  удалить можно только то, что скрипт сам признал каталогом окружения (Принцип V).
- **Note**: `test -O` не входит в POSIX, но поддерживается `dash`, BusyBox `ash`,
  `bash`, `ksh` и `zsh` — всеми `sh`, которые встречаются на целях матрицы. Без
  поддержки `-O` выражение даёт ошибку → каталог считается чужим (отказ в сторону
  безопасности).

## R3. Активная сессия

- **Decision**: маркер `sessions/<sid>` с pid; сессия активна, если `kill -0 <pid>`
  успешен. Мёртвые маркеры — «следы сбоя», показываются и удаляются без `--force`.
  Решение «есть активные — отказ» принимает скрипт `clean`/`prune` непосредственно
  перед удалением и при отказе ничего не трогает.
- **Rationale**: тот же критерий, что у `reconcile` (001 §FR-006); проверка на цели
  сокращает окно гонки между проверкой и удалением.

## R4. Время последнего использования и объём

- **Decision**: при входе с `--keep` клиент передаёт `XXH_NOW=<секунды Unix>`, скрипт
  пишет его в `<root>/.keep` (раньше файл был пустым). Объём — `du -sk`, если `du`
  есть; иначе «неизвестно».
- **Rationale**: `date`/`stat` вне контракта хоста; часы клиента достаточно точны для
  «когда я тут был». Старые `.keep` без содержимого → «неизвестно».

## R5. Актуальность компонентов

- **Decision**: функция `plan_components(platform, eff, env, plugins)` в `xxh-core`
  возвращает компоненты, которые вход доставил бы этой цели (шелл-пакет под платформу,
  env/terminfo, плагины по маске платформы), с подписью. Компонент на цели
  «актуален», если его адрес есть в плане, иначе «устарел»; компоненты плана, которых
  нет на цели, — «будут доставлены». `establish` использует ту же функцию.
- **Rationale**: одна логика для входа и для отчёта — отчёт не может разойтись с
  поведением. Адрес после 023 не зависит от формата архива и не требует упаковки.

## R6. Выборочная очистка

- **Decision**: `xxh clean <цель> --stale` → `sh -s -- prune <force> <hash>…`, где
  хеши — актуальные адреса (оставить). Скрипт удаляет из `cache/` всё остальное,
  включая брошенные `.tmp.*`; каталог окружения, `.keep` и сессии не трогает.
  Аргументы проверяются как 64-символьный hex.
- **Rationale**: «оставить список» безопаснее «удалить список»: клиент не может
  указать путь вне `cache/`. Длина аргументов — десятки адресов, далеко от лимитов.

## R7. Один транспорт для входа и команд обслуживания

- **Decision**: `impl<T: Transport + ?Sized> Transport for Box<T>` в `xxh-transport` и
  фабрика `open_transport(target, eff) -> Box<dyn Transport>` в CLI, которую
  используют вход, `status` и `clean`.
- **Rationale**: Принцип III — выбор бэкенда в одном месте; сейчас он продублирован
  ветками в `connect.rs`.

## R8. Код выхода

- **Decision**: новый класс «target», код `50`: `clean` отказался из-за активных
  сессий или не смог удалить часть файлов. Транспорт — `10`, конфиг/цель в
  командной строке — `40`, как при входе.
- **Rationale**: FR-005 требует ненулевой код при частичной очистке; скрипту нужно
  отличать «цель недостижима» от «на цели осталось».
