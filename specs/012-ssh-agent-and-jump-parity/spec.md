# Feature Specification: Агент ключей и промежуточные хосты во встроенном SSH-клиенте

**Feature Branch**: `012-ssh-agent-and-jump-parity`

**Created**: 2026-10-01

**Status**: Draft

**Priority**: P1

**Summary**: Встроенный SSH-клиент работает с ssh-agent и через bastion так же, как системный ssh, без переключения транспорта

**Input**: User description: "ProxyJump/bastion и agent forwarding для встроенного SSH-бэкенда: при `--transport ssh` это работает через системный клиент, а во встроенном аутентификация через ssh-agent отмечена в коде как отложенная; нужно довести до паритета."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Ключи из агента (Priority: P1)

У пользователя ключи хранятся только в агенте (аппаратный ключ, менеджер паролей).
Вход встроенным клиентом работает без указания файла ключа и без переключения на
системный ssh.

**Why this priority**: конституция (Принцип V) требует уважать ssh-agent; сегодня для
таких пользователей транспорт по умолчанию не работает.

**Independent Test**: ключ есть только в агенте; `xxh <хост>` с транспортом по
умолчанию входит успешно.

**Acceptance Scenarios**:

1. **Given** ключ загружен в агент и файла ключа нет, **When** пользователь входит
   встроенным клиентом, **Then** аутентификация проходит через агент.
2. **Given** агент недоступен, **When** пользователь входит, **Then** используются
   остальные способы аутентификации, как раньше.
3. **Given** в агенте несколько ключей, **When** пользователь входит, **Then** подходящий
   ключ подбирается без превышения лимита попыток сервера, с учётом настроек выбора
   ключа в конфигурации SSH.

---

### User Story 2 - Вход через промежуточный хост (Priority: P1)

Целевой хост доступен только через bastion, описанный в конфигурации SSH пользователя.
Вход встроенным клиентом проходит по цепочке так же, как системным.

**Why this priority**: типичная корпоративная топология; требование Принципа V.

**Independent Test**: цель достижима только через промежуточный хост; `xxh <хост>`
входит, окружение доставлено, после выхода цель чиста.

**Acceptance Scenarios**:

1. **Given** в конфигурации SSH для хоста задан промежуточный хост, **When**
   пользователь входит, **Then** соединение устанавливается через него.
2. **Given** цепочка из нескольких промежуточных хостов, **When** пользователь входит,
   **Then** проходит вся цепочка.
3. **Given** промежуточный хост недоступен или отклонил аутентификацию, **When**
   пользователь входит, **Then** ошибка транспорта называет именно это звено.

---

### User Story 3 - Проброс агента на цель (Priority: P3)

Пользователь явно разрешает проброс агента, чтобы с цели работать с git или идти
дальше своими ключами.

**Why this priority**: удобно, но несёт риск и должно быть только явным.

**Independent Test**: с разрешённым пробросом в сессии виден агент с ключами клиента;
без разрешения — нет.

**Acceptance Scenarios**:

1. **Given** проброс разрешён для хоста, **When** пользователь входит, **Then** в сессии
   доступен агент клиента.
2. **Given** проброс не разрешён, **When** пользователь входит, **Then** агент в сессии
   недоступен.

---

### Edge Cases

- Ключ хоста промежуточного звена неизвестен или изменился — проверка известных хостов
  действует для каждого звена.
- Агент требует подтверждения использования ключа — ожидание не считается зависанием,
  действует таймаут подключения.
- Конфигурация задаёт произвольную команду-посредник вместо промежуточного хоста —
  поведение определено: поддерживается либо даётся подсказка использовать системный
  транспорт.
- Разные пользователи и ключи на разных звеньях цепочки.
- Данные агента и ключей не попадают в журналы.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Встроенный SSH-клиент MUST поддерживать аутентификацию ключами из агента
  пользователя.
- **FR-002**: Порядок и выбор способов аутентификации MUST соответствовать конфигурации
  SSH пользователя.
- **FR-003**: Встроенный SSH-клиент MUST устанавливать соединение через промежуточные
  хосты, заданные в конфигурации SSH, включая цепочки.
- **FR-004**: Проверка ключей хостов MUST выполняться для каждого звена цепочки.
- **FR-005**: Ошибка на промежуточном звене MUST называть это звено и относиться к
  классу «транспорт».
- **FR-006**: Проброс агента на цель MUST быть выключен по умолчанию и включаться только
  явно — флагом, настройкой хоста или конфигурацией SSH.
- **FR-007**: Для конфигураций, которые встроенный клиент не поддерживает, система MUST
  сообщать об этом явно и подсказывать системный транспорт.
- **FR-008**: Секреты, содержимое ключей и обмен с агентом MUST NOT журналироваться.
- **FR-009**: Доставка окружения и очистка через промежуточные хосты MUST давать те же
  гарантии, что и прямое соединение; на промежуточных хостах MUST NOT оставаться
  артефактов.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Пользователь, чьи ключи есть только в агенте, входит транспортом по
  умолчанию без дополнительных флагов.
- **SC-002**: Хост, достижимый системным ssh через промежуточные хосты по конфигурации
  пользователя, достижим и встроенным клиентом без изменения конфигурации.
- **SC-003**: Интеграционный сценарий «вход через промежуточный хост → свой шелл →
  выход → чисто» проходит на обязательной матрице образов.
- **SC-004**: Без явного разрешения агент клиента недоступен на цели в 100% сессий.

## Assumptions

- Системный транспорт остаётся режимом совместимости для экзотических конфигураций
  (Принцип III).
- Вход с цели дальше со своим окружением — фича 018.
