# Research: Быстрый повторный вход

## R1. Откуда задержка (замер 2026-10-01)

`xxh docker:<c> --keep -- true` в развёрнутое окружение — ~2,8 с; по этапам с `-v`:
~2,5 с между «detect platform» и «deliver components» — упаковка шелла и плагинов
(48 МБ) в tar+gzip. Сообщение «sending 2, reused 4» при неизменном окружении — env и
terminfo пересылаются каждый раз: архив содержит mtime временного каталога.

## R2. Адрес компонента

- **Decision**: blake3 от канонического описания дерева: для каждого элемента в
  порядке сортировки относительных путей — тип (каталог/файл), путь, биты прав
  (`mode & 0o777`), длина и содержимое файла. Симлинки разыменовываются (как и при
  упаковке).
- **Rationale**: вычисляется без сжатия (blake3 — гигабайты в секунду); не зависит от
  mtime, владельца, формата архива и версии библиотек сжатия; один адрес для `gz` и
  `zst`. Содержимое читается всегда — изменение без смены размера и mtime
  обнаруживается (FR-004).
- **Alternatives**: хешировать детерминированный tar — всё равно нужно собирать архив;
  запоминать адрес по (размер, mtime) — пропускает правки с сохранением mtime.

## R3. Ленивая детерминированная упаковка

- **Decision**: `Component` хранит адрес и источник (каталог либо готовые байты);
  `payload()` упаковывает по требованию. Архив собирается вручную: элементы в порядке
  сортировки, mtime — фиксированная константа, uid/gid 0, права из файла.
- **Rationale**: упаковка нужна только для отсутствующих на цели компонентов;
  детерминированность делает архив пригодным для кеша и воспроизводимым между
  клиентами. Нулевой mtime вызывает у GNU tar предупреждение «implausibly old time
  stamp», поэтому используется фиксированная дата 2000-01-01.

## R4. Клиентский кеш архивов

- **Decision**: `~/.cache/xxh/packed/<hash>.<fmt>`; файл = 32 байта blake3 архива +
  архив; запись атомарная (временный файл + rename); при чтении сумма проверяется,
  несовпадение — упаковка заново. Не более 64 записей (старые по mtime удаляются).
  Ошибки кеша не фатальны. Сгенерированные компоненты (env, terminfo) в кеш не
  пишутся — они крошечные.
- **Rationale**: FR-003 и FR-005 — первый вход на новый хост с тем же плагином не
  пережимает 48 МБ заново.

## R5. Совместимость

Адреса меняются один раз: сохранённые (`--keep`) окружения получат компоненты заново,
старые каталоги `cache/<старый-хеш>` останутся до очистки (005 `xxh clean`). Протокол
`recv`/`list-cache` не меняется.
