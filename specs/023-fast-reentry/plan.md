# Implementation Plan: Быстрый повторный вход без повторной упаковки и пересылки

**Branch**: `023-fast-reentry` | **Date**: 2026-10-01 | **Spec**: [spec.md](spec.md)

**Input**: Feature specification from `/specs/023-fast-reentry/spec.md`

## Summary

Сейчас адрес компонента — blake3 от *упакованного* архива, поэтому клиент обязан
упаковать (tar + gzip/zstd) каждый компонент при каждом входе, чтобы просто узнать,
есть ли он на цели; а архив включает времена файлов, так что сгенерированные
компоненты получают новый адрес при каждом запуске.

Решение: адрес компонента — хеш его **дерева** (отсортированные пути, права,
содержимое). Он вычисляется чтением файлов без сжатия и не зависит от времени и
формата архива. Упаковка становится ленивой — только для компонентов, которых на
цели нет, — и детерминированной; упакованный архив сохраняется в клиентском кеше с
контрольной суммой. Протокол bootstrap и раскладка на цели не меняются: цель
по-прежнему получает `recv <hash> <fmt>` и хранит `cache/<hash>`.

## Technical Context

**Language/Version**: Rust 1.85, edition 2024

**Primary Dependencies**: существующие `blake3`, `tar`, `flate2`, `zstd`,
`directories` — новых нет

**Storage**: клиентский кеш упакованных архивов `~/.cache/xxh/packed/<hash>.<fmt>`
(переопределение `XXH_PACK_CACHE_DIR`), ограниченный по числу записей

**Testing**: unit — стабильность адреса, чувствительность к содержимому и правам,
детерминированность архива, поведение кеша; интеграция — повторный вход с `--keep`
ничего не передаёт (существующий `cache_reuse` расширяется), замер времени вручную

**Target Platform**: без изменений

**Project Type**: CLI-инструмент, многокрейтовый workspace

**Performance Goals**: запуск команды в сохранённое окружение на локальной цели — не
более секунды сверх подключения (SC-002); первый вход не медленнее прежнего (SC-004)

**Constraints**: изменение содержимого обнаруживается всегда (без опоры на
mtime/размер); повреждённый клиентский кеш не ломает вход; протокол цели неизменен

**Scale/Scope**: `crates/xxh-core/src/deploy.rs` (основное), точечные правки
`session.rs`; один расширенный интеграционный тест
