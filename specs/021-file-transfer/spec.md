# Feature Specification: Передача файлов на цель и с цели

**Feature Branch**: `021-file-transfer`

**Created**: 2026-10-01

**Status**: Draft

**Priority**: P3

**Summary**: `xxh cp` копирует файлы между клиентом и целью тем же способом адресации — в том числе в контейнеры без sshd

**Input**: User description: "scp-подобная передача файлов: `xxh cp` поверх того же транспорта; особенно полезно для контейнеров без sshd."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Скопировать файл на цель и обратно (Priority: P1)

Пользователь копирует файл или каталог с клиента на цель или с цели на клиент, адресуя
цель так же, как при входе, — будь то SSH-хост или контейнер.

**Why this priority**: при работе в чужом окружении постоянно нужно забрать журнал или
положить скрипт; для контейнеров и встроенного транспорта единого способа сейчас нет.

**Independent Test**: скопировать файл на цель, обратно, сверить содержимое и права.

**Acceptance Scenarios**:

1. **Given** файл на клиенте, **When** пользователь копирует его на цель по указанному
   пути, **Then** файл появляется там с тем же содержимым и правами.
2. **Given** файл на цели, **When** пользователь копирует его на клиент, **Then**
   получена точная копия.
3. **Given** каталог, **When** запрошено рекурсивное копирование, **Then** структура,
   содержимое и права сохранены.
4. **Given** цель — контейнер без sshd, **When** выполняется копирование, **Then** оно
   работает так же, как для SSH-хоста.

---

### User Story 2 - Не оставлять следов сверх запрошенного (Priority: P2)

Копирование не разворачивает окружение и не оставляет на цели ничего, кроме
запрошенных файлов.

**Why this priority**: принцип zero-footprint распространяется на все команды.

**Independent Test**: после копирования на цели есть только скопированный файл;
каталога окружения xxh нет.

**Acceptance Scenarios**:

1. **Given** чистая цель, **When** выполнено копирование на неё, **Then** единственное
   изменение на цели — запрошенные файлы.
2. **Given** передача прервана, **When** проверяется место назначения, **Then** там нет
   частично записанного файла под конечным именем.

---

### Edge Cases

- Место назначения существует — перезапись только по явному согласию либо флагу.
- Недостаточно прав или места на цели — ошибка называет причину.
- Очень большой файл — передача потоковая, без загрузки целиком в память; виден прогресс.
- Имена файлов с пробелами и спецсимволами — передаются без искажений.
- Символические ссылки — копируются как ссылки либо разыменовываются по явному выбору.
- Копирование между двумя удалёнными целями — определено: поддерживается через клиент
  либо отклоняется с объяснением.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST предоставлять команду копирования файлов и каталогов с
  клиента на цель и с цели на клиент.
- **FR-002**: Адресация цели MUST быть той же, что при входе, для всех поддерживаемых
  семейств целей.
- **FR-003**: Передача MUST идти только через установленное соединение выбранного
  транспорта.
- **FR-004**: Содержимое, права доступа и структура каталогов MUST сохраняться.
- **FR-005**: Существующие файлы MUST NOT перезаписываться без явного согласия.
- **FR-006**: Прерванная передача MUST NOT оставлять частично записанный файл под
  конечным именем.
- **FR-007**: Копирование MUST NOT оставлять на цели ничего, кроме запрошенных файлов.
- **FR-008**: Передача MUST быть потоковой и показывать прогресс для больших объёмов.
- **FR-009**: Требования к цели MUST NOT превышать уже зафиксированных требований к
  хосту.
- **FR-010**: Ошибки соединения MUST относиться к классу «транспорт»; ошибки файловой
  системы MUST называть путь и причину.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Скопированные файлы побайтно совпадают с исходными в 100% случаев.
- **SC-002**: Пользователь копирует файл в контейнер без sshd одной командой, не зная,
  какой рантайм используется.
- **SC-003**: После копирования на цели нет ни одного артефакта xxh.
- **SC-004**: Передача файла в один гигабайт не увеличивает потребление памяти клиента
  более чем на несколько десятков мегабайт.

## Assumptions

- Синхронизация каталогов с вычислением различий (как rsync) — вне рамок.
- Отображение прогресса согласуется с фичей 015.
- Перенос личных конфигов в сессию — фича 010, а не эта команда.
