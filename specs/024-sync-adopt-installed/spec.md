# Feature Specification: Синхронизация без lock-файла принимает уже установленное

**Feature Branch**: `024-sync-adopt-installed`

**Created**: 2026-10-14

**Status**: Implemented

**Priority**: P1

**Summary**: `xxh sync` без lock-файла не переустанавливает то, что уже стоит из того же источника, а записывает его в lock — без сети и сборок

**Input**: User description: "xxh sync без lock-файла не должен переустанавливать уже установленное. Сейчас (013 C-L6), если для объявленного плагина или шелла нет записи в lock, sync ставит его заново из источника. Для nixpkgs-источников это nix build по плавающей ветке nixpkgs, что часто означает многочасовую сборку pkgsStatic из исходников без вывода прогресса — sync и активация home-manager выглядят зависшими. Типичный случай: пользователь убрал lockFile из NixOS/home-manager конфигурации (lock необязателен), а все плагины уже стоят в реестре. Нужно: если записи lock нет, но плагин/шелл с тем же именем уже установлен из того же источника — принять установленное (записать его source/revision/hash в lock) без сети и сборки. Обновление версий остаётся за явными командами (xxh plugin update и т.п.). Если установлен из другого источника или не установлен — как раньше, установка из источника. Связь: 013 C-L4/C-L6, FR-005; прогресс долгих установок — отдельная фича 015."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Отказ от lock-файла в декларативной конфигурации (Priority: P1)

Пользователь объявляет плагины и шелл в конфигурации NixOS/Home Manager и больше не
хранит рядом с ней `xxh.lock`. Всё объявленное у него уже установлено. После
переключения конфигурации `xxh sync` при активации завершается за секунды: он
записывает установленное в собственный lock-файл и ничего не скачивает и не собирает.

**Why this priority**: сейчас в этом случае sync заново собирает каждый
nixpkgs-плагин по сдвинувшейся ветке nixpkgs. Это часы компиляции без вывода:
активация системы выглядит зависшей.

**Independent Test**: установить плагины (git и nixpkgs) и шелл через `xxh sync`,
удалить lock-файл, повторить `xxh sync` без сети — команда успешна, установленное не
изменилось, lock-файл восстановлен с теми же версиями.

**Acceptance Scenarios**:

1. **Given** плагин установлен из источника S, lock-файла нет, **When** выполняется
   `xxh sync` с объявлением этого плагина из S, **Then** плагин не переустанавливается,
   в lock появляется запись с источником S и хешем установленного содержимого, отчёт
   сообщает «без изменений».
2. **Given** шелл установлен из источника S, lock-файла нет, **When** выполняется
   `xxh sync`, **Then** шелл не переустанавливается и записывается в lock.
3. **Given** установленное принято в lock, **When** lock-файл переносится на другую
   машину и там выполняется `xxh sync`, **Then** ставятся те же версии, что на
   исходной машине (013 C-L5).

---

### User Story 2 - Смена источника по-прежнему переустанавливает (Priority: P2)

Пользователь меняет источник плагина в конфигурации. Принимать старую установку
нельзя — она из другого источника.

**Why this priority**: без этого принятие установленного скрывало бы смену источника.

**Independent Test**: установить плагин из S1, объявить его из S2, удалить lock,
выполнить sync — плагин установлен из S2.

**Acceptance Scenarios**:

1. **Given** плагин установлен из S1 и объявлен из S2, записи lock нет, **When**
   выполняется `xxh sync`, **Then** плагин устанавливается из S2 и записывается в lock
   (как в 013 C-L6).
2. **Given** объявленное не установлено, записи lock нет, **When** выполняется
   `xxh sync`, **Then** оно устанавливается из источника (как в 013 C-L6).

### Edge Cases

- Установленный git-плагин, у которого неизвестна ревизия (установлен до этой
  фичи): записать его в lock без ревизии нельзя — на другой машине его не
  воспроизвести. Такой плагин ставится из источника, как раньше. Git-установка
  быстрая; проблема долгих сборок касается nixpkgs-источников, у которых ревизии нет.
- Шелл установлен, но не хватает сборок под Linux-платформы: шелл не принимается, а
  доустанавливается из источника (как при совпадении с lock в 013).
- Lock-файл есть, но в нём нет записи для этого объявления (новое объявление): то же
  правило, что и без lock-файла.
- Lock-файл только для чтения (его подставляет Nix): принятые записи печатаются для
  переноса (013 C-L8).
- Повреждённая установка (содержимое не совпадает с записанным хешем) обнаруживается
  проверкой целостности реестра. Принятие установленного эту проверку не отменяет.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Если для объявления нет записи lock (или её источник отличается от
  объявленного) и под тем же именем уже установлено содержимое из того же источника,
  `xxh sync` MUST принять установленное: записать в lock источник, ревизию (если она
  есть у источника) и хеш, не обращаясь к сети и не запуская сборок. Это уточняет
  013 C-L6.
- **FR-002**: Принятое объявление MUST попадать в отчёт как «без изменений».
- **FR-003**: Если установленное получено из другого источника или не установлено,
  `xxh sync` MUST устанавливать из источника, как в 013 C-L6.
- **FR-004**: Для источников с ревизией (git) установленное MUST приниматься только
  при известной ревизии установки; иначе — установка из источника.
- **FR-005**: Установка плагина MUST сохранять ревизию источника вместе с
  установленным, чтобы её можно было принять позже.
- **FR-006**: Шелл MUST приниматься только при наличии сборок под все Linux-платформы
  (условие, при котором 013 считает шелл совпадающим с lock).
- **FR-007**: Поведение при наличии записи lock (013 C-L4, C-L5) MUST остаться
  прежним.
- **FR-008**: Обновление версий (`xxh plugin update` и аналоги) MUST оставаться
  единственным способом сдвинуть принятое на новую версию источника.

### Key Entities

- **Запись установки**: имя, источник, хеш содержимого, ревизия (новое для плагинов).
- **Запись lock**: источник, ревизия, хеш — без изменений формата (013).

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: `xxh sync` без lock-файла, когда всё объявленное уже установлено из
  объявленных источников, завершается менее чем за 2 секунды и без сетевых обращений.
- **SC-002**: Lock-файл, восстановленный таким sync, на другой машине даёт те же хеши
  содержимого, что на исходной.
- **SC-003**: Активация декларативной конфигурации без lock-файла не запускает ни
  одной сборки для уже установленных nixpkgs-плагинов.

## Assumptions

- «Тот же источник» означает равенство разобранной спецификации источника
  (тип и адрес/атрибут), а не строки конфигурации.
- Плагины, установленные до этой фичи, ревизии не хранят. Nixpkgs-плагины ревизии не
  имеют, поэтому принимаются сразу; git-плагины старой установки один раз ставятся
  заново (быстро), после чего принимаются.
- Вывод прогресса долгих установок — фича 015, здесь не решается.
- Формат lock-файла и NixOS/Home Manager-модули не меняются: `lockFile` уже
  необязателен.
