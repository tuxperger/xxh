# Feature Specification: Прогрев и обслуживание группы целей

**Feature Branch**: `020-multi-target-warmup`

**Created**: 2026-10-01

**Status**: Draft

**Priority**: P3

**Summary**: Заранее и параллельно разложить окружение на группу хостов, чтобы первый вход на каждый был мгновенным

**Input**: User description: "Параллельный прогрев: `xxh warm host1 host2 …` заранее раскладывает кэш на группу хостов."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Прогреть группу хостов (Priority: P1)

Пользователь получил доступ к десятку серверов или обновил свои плагины. Одной командой
он заранее доставляет окружение на все хосты параллельно; последующий вход на любой из
них не ждёт передачи.

**Why this priority**: первая доставка — самая долгая часть входа; при работе с парком
машин она повторяется на каждой.

**Independent Test**: прогреть несколько тестовых целей; вход на каждую сообщает, что
все компоненты переиспользованы.

**Acceptance Scenarios**:

1. **Given** список целей, **When** пользователь выполняет прогрев, **Then** окружение
   доставлено на каждую и сохранено для последующих входов.
2. **Given** прогретая цель, **When** пользователь входит на неё, **Then** ни один
   компонент не передаётся повторно.
3. **Given** одна из целей недоступна, **When** идёт прогрев, **Then** остальные цели
   обрабатываются, а в итоге перечислены успешные и неуспешные с причинами.
4. **Given** цель уже прогрета актуальным окружением, **When** прогрев повторяется,
   **Then** на неё ничего не передаётся.

---

### User Story 2 - Именованные группы (Priority: P2)

Пользователь описывает группы хостов в конфиге и обращается к группе по имени — для
прогрева, проверки состояния и очистки.

**Why this priority**: избавляет от перечисления хостов и делает обслуживание
повторяемым.

**Independent Test**: объявить группу из двух целей, выполнить прогрев и очистку по
имени группы.

**Acceptance Scenarios**:

1. **Given** группа объявлена в конфигурации, **When** пользователь указывает её имя,
   **Then** операция применяется ко всем её целям.
2. **Given** группа, **When** пользователь запрашивает состояние или очистку, **Then**
   операция выполняется по всем целям с общим итогом.

---

### Edge Cases

- Цели разных платформ — на каждую едут компоненты её платформы.
- Цели разных семейств (SSH и контейнеры) в одном списке.
- Интерактивная аутентификация (пароль, подтверждение ключа хоста) при параллельной
  работе — цель пропускается с объяснением, а не блокирует остальные.
- Ограничение параллелизма, чтобы не перегружать канал и агент ключей.
- Прерывание пользователем — начатые доставки завершаются корректно либо не оставляют
  неполных компонентов.
- Прогрев явно оставляет окружение на цели — пользователь предупреждён, что это
  отступление от режима «чистить за собой».

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST предоставлять команду доставки окружения на несколько целей
  без открытия сессии.
- **FR-002**: Доставка на разные цели MUST выполняться параллельно с настраиваемым
  ограничением.
- **FR-003**: Сбой на одной цели MUST NOT прерывать обработку остальных.
- **FR-004**: По завершении система MUST выдавать итог по каждой цели и общий код
  возврата, отражающий наличие сбоев.
- **FR-005**: Прогрев MUST сохранять окружение на цели только как явное действие
  пользователя и MUST сообщать об этом.
- **FR-006**: Пользователь MUST иметь возможность объявить именованные группы целей в
  конфигурации и использовать имя группы вместо списка.
- **FR-007**: Групповые операции MUST включать как минимум прогрев, просмотр состояния и
  очистку.
- **FR-008**: Цель, требующая интерактивного ввода, MUST пропускаться с объяснением.
- **FR-009**: Вывод параллельных операций MUST оставаться читаемым и относимым к целям;
  MUST существовать машиночитаемый формат итога.
- **FR-010**: Неполная доставка MUST NOT оставлять компонент, считающийся доставленным.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Прогрев десяти целей занимает не более чем вдвое больше времени, чем
  прогрев одной самой медленной из них.
- **SC-002**: После прогрева вход на любую из целей не передаёт ни одного компонента.
- **SC-003**: Недоступность части целей не мешает прогреву остальных в 100% случаев.
- **SC-004**: Одной командой пользователь возвращает всю группу в чистое состояние.

## Assumptions

- Зависит от фичи 005 (состояние и очистка одной цели) и согласуется с фичей 014
  (целостность сохранённого окружения).
- Параллельное выполнение произвольной команды на группе — вне рамок; для этого есть
  специализированные инструменты.
