# Contract: цель Kubernetes (`k8s:`)

Продолжает 002 `contracts/target-addressing.md` и `transport-trait.md`.

## Адресация

- **C-K8S1**: `k8s:[namespace/]pod[:container]`. Каждая часть непуста; не больше
  одного `/` и одного `:` после префикса. Нарушение — ошибка конфигурации до
  подключения (код возврата класса config).
- **C-K8S2**: префикс `k8s` попадает в перечень поддерживаемых в ошибке неизвестного
  префикса и в автодополнение префиксов. Имена подов не дополняются (007 C-K9).
- **C-K8S3**: `--kube-context NAME` выбирает контекст kubeconfig; для не-k8s целей —
  ошибка конфигурации. Без флага — текущий контекст; `KUBECONFIG` и прочее окружение
  наследуются нетронутыми.
- **C-K8S4**: для `k8s:` отклоняются `-i/--identity`, `-A/--forward-agent`,
  `--transport`, `--runtime`, `-l/--user`. Ключ конфига `user` к k8s-цели не
  применяется.
- **C-K8S5**: ключ конфига хоста для k8s-цели — её адрес без префикса
  (`[hosts."ns/pod"]`), как у docker-цели — ссылка на контейнер.

## Подключение

- **C-K8S6**: `kubectl` не в PATH → `BackendUnavailable` «kubectl is not installed».
- **C-K8S7**: проверка пода — один `kubectl get pod` с таймаутом
  `connect_timeout_s`; различимы: пода нет (`Connect`), нет прав (`Auth`), кластер
  недоступен (`Connect`), таймаут (`Timeout`), под не `Running` (`Connect`, с фазой),
  контейнера нет (`Connect`, с перечнем контейнеров).
- **C-K8S8**: без указанного контейнера — `kubectl.kubernetes.io/default-container`,
  иначе первый в спецификации; выбранный сообщается строкой прогресса
  `container <имя>`.
- **C-K8S9**: в ошибки не попадают stderr `kubectl`, адрес API-сервера, токены,
  содержимое kubeconfig; в журнал — только контекст, пространство имён, под и
  контейнер.

## Обмен данными

- **C-K8S10**: единственный канал — `kubectl exec … -c <контейнер> -- sh -c …`
  (`-c` всегда явный). Никаких `cp`, `debug`, `attach`, `patch`, `annotate`.
- **C-K8S11**: `exec_stream` — `exec -i` без `-t`, stdio клиента, код возврата по
  004 C-X3; `open_pty` — `exec -i -t` на локальном PTY, переменные сессии
  экспортируются внутри `sh -c` с одинарным экранированием; значения не журналируются.
- **C-K8S12**: нет `sh` в контейнере — та же ошибка доставки, что у docker (002 C-C6).
- **C-K8S13**: семейство охраняется: бэкенд k8s отвергает SSH и docker-цели, docker
  и SSH-бэкенды отвергают k8s-цель с `BackendUnavailable` (C-T6).
