# Feature Specification: Дополнительные транспорты — Kubernetes, другие рантаймы, локальная цель

**Feature Branch**: `016-additional-transports`

**Created**: 2026-10-01

**Status**: Draft

**Priority**: P2

**Summary**: Своё окружение в поде Kubernetes, в контейнерах nerdctl/incus/nspawn и в локальной «песочнице» — той же командой и с теми же гарантиями

**Input**: User description: "Новые транспорты: `kubectl exec` (`k8s:ns/pod`) и nerdctl уже упомянуты в коде как будущие; туда же ложатся systemd-nspawn/machinectl, lxc/incus, WSL и `local:` для проверки окружения без сети."

## User Scenarios & Testing *(mandatory)*

### User Story 1 - Под Kubernetes со своим окружением (Priority: P1)

Пользователь отлаживает сервис в кластере. Одной командой он входит в под со своим
шеллом и инструментами — без sshd в поде и без изменения образа; после выхода под чист.

**Why this priority**: самый востребованный класс целей после SSH и локальных
контейнеров; минимальные образы в кластерах — именно тот случай, где своё окружение
ценнее всего.

**Independent Test**: войти в под в тестовом кластере, выполнить команду в доставленном
окружении, выйти, убедиться в чистоте пода.

**Acceptance Scenarios**:

1. **Given** запущенный под и доступ пользователя к кластеру, **When** пользователь
   выполняет `xxh k8s:<пространство>/<под>`, **Then** он получает сессию своего шелла в
   поде.
2. **Given** под с несколькими контейнерами, **When** пользователь указывает контейнер,
   **Then** сессия открывается в нём; без указания — в контейнере по умолчанию с
   сообщением, какой выбран.
3. **Given** сессия завершена, **When** проверяется под, **Then** артефактов окружения
   нет.
4. **Given** у пользователя нет прав на вход в под, **When** он пытается войти,
   **Then** ошибка транспорта называет причину; учётные данные кластера не выводятся.

---

### User Story 2 - Локальная цель для проверки окружения (Priority: P2)

Пользователь хочет проверить, как выглядит его перенесённое окружение, не подключаясь
никуда: окружение разворачивается во временном каталоге на его же машине.

**Why this priority**: ускоряет отладку плагинов и конфигов и даёт быстрый способ
убедиться в работоспособности установки.

**Independent Test**: `xxh local:` открывает сессию своего шелла из временного каталога;
после выхода каталог удалён, домашний каталог не изменён.

**Acceptance Scenarios**:

1. **Given** настроенное окружение, **When** пользователь выполняет `xxh local:`,
   **Then** открывается сессия, развёрнутая по тем же правилам, что и на удалённой цели.
2. **Given** сессия завершена, **When** проверяется машина, **Then** временный каталог
   удалён и собственные файлы пользователя не изменены.

---

### User Story 3 - Другие рантаймы контейнеров и машин (Priority: P3)

Пользователь работает с nerdctl, incus/lxc или systemd-nspawn и входит в их запущенные
контейнеры так же, как в docker и podman.

**Why this priority**: расширяет охват; для каждой из этих сред уже есть обходной путь
через SSH.

**Independent Test**: для каждого рантайма — вход в запущенный контейнер, команда в
окружении, выход, чистота.

**Acceptance Scenarios**:

1. **Given** запущенный контейнер поддерживаемого рантайма, **When** пользователь
   адресует его префиксом этого рантайма, **Then** он получает сессию с теми же
   возможностями и гарантиями, что и для docker/podman.
2. **Given** рантайм не установлен, **When** пользователь адресует цель его префиксом,
   **Then** ошибка транспорта сообщает об отсутствии рантайма до каких-либо действий.

---

### Edge Cases

- Под перезапущен или удалён во время сессии — ошибка транспорта, без зависания.
- В контейнере пода нет `sh` — явная ошибка доставки (см. фичу 022).
- Файловая система контейнера доступна только для чтения — используется доступный для
  записи временный каталог либо явная ошибка.
- Несколько контекстов кластера — используется текущий, с возможностью указать иной.
- Неизвестный префикс цели — ошибка использования с перечнем поддерживаемых.
- Опции, применимые только к SSH, отклоняются для этих целей до подключения.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: Система MUST поддерживать адресацию пода Kubernetes с указанием
  пространства имён, пода и, опционально, контейнера и контекста.
- **FR-002**: Система MUST поддерживать локальную цель, разворачивающую окружение во
  временном каталоге клиента.
- **FR-003**: Система MUST поддерживать запущенные контейнеры дополнительных рантаймов
  (как минимум nerdctl, incus/lxc, systemd-nspawn) через их собственные префиксы.
- **FR-004**: Для всех новых целей MUST действовать единая семантика: определение
  платформы, доставка, кеширование, очистка, плагины и флаги сессии — как у существующих
  транспортов.
- **FR-005**: Образы, манифесты и спецификации подов и контейнеров MUST NOT
  модифицироваться.
- **FR-006**: Аутентификация MUST опираться на уже имеющийся у пользователя доступ к
  кластеру или рантайму; система MUST NOT вводить собственные учётные данные и MUST NOT
  журналировать чужие.
- **FR-007**: Отсутствие клиента кластера или рантайма MUST отключать только
  соответствующий транспорт с понятным сообщением.
- **FR-008**: Добавление этих транспортов MUST NOT требовать изменений в логике
  развёртывания, плагинов и очистки.
- **FR-009**: Опции, специфичные для одного семейства целей, MUST отклоняться для
  других до подключения.
- **FR-010**: Каждый новый транспорт MUST быть покрыт интеграционным сценарием против
  реальной среды с проверкой чистоты цели.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: Пользователь входит в под кластера со своим окружением одной командой, без
  подготовки пода.
- **SC-002**: После выхода под, контейнер или локальный каталог чисты в 100% сценариев,
  образ не изменён.
- **SC-003**: Набор возможностей сессии одинаков для всех транспортов (проверяется
  общим набором сценариев).
- **SC-004**: `xxh local:` даёт рабочую сессию менее чем за две секунды на прогретом
  клиенте.

## Assumptions

- Продолжение фичи 002: новые цели — дополнительные реализации за существующим
  интерфейсом транспорта (Принцип III).
- Создание и запуск подов/контейнеров — вне рамок; цель уже запущена.
- WSL рассматривается как частный случай локального рантайма и может быть выделен в
  отдельную фичу, если потребует иной адресации.
- Каждый транспорт может поставляться отдельной итерацией; порядок — Kubernetes,
  локальная цель, остальные.
